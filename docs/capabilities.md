# 单机版能力清单

更新：2026-11-15。

这份清单回答一个问题：**单机版现在能做什么，每项能力从哪里调用。** 写给接手的人和接入的 AI 工作台看。

## 怎么用

- 每项能力都有 HTTP 接口（`acornfox/internal/apiserver/apiserver.go`）、CLI（`acornfox/internal/cli/`）和 Skill（`skills/acornfox/SKILL.md`）。网页控制台也调同一个接口。
- 命令的参数以 `acornfox help` 和各命令的 `-h` 为准，本文件不重复抄命令细节。
- 加全局参数 `--json` 时，成功输出 `{"ok":true, …}`，失败输出带诊断的 JSON。

## 影响分级

- **只读**：随时可以调用。
- **会改数据**：改应用、配置或服务器上的状态，Skill 里写明什么时候要先问用户。
- **会删数据**：`delete --volumes`、移除数据库这类不可恢复的操作，必须用户明确要求。

| 应用状态 | 应用在不在跑、地址是什么。只在内部网络的应用（v0.6.0 起，`exposure: internal`，数据库、缓存这类）没有地址：`url` 是空的，没有 `lan_url`、`open_hint`，带 `internal_only: true` 和 `internal_note`（“只在内部网络，给别的应用用”）；`apps` 的人读输出在地址那一栏写这句话，`status` 写“访问：只在内部网络……”和别的应用连它用的“名字:容器内端口”。只本机能打开的应用（`exposure: local`），Linux 上地址是 `http://127.0.0.1:端口`、带 `local_only: true` 和 `open_hint`（怎么从自己电脑打开，见下面“打开应用”），`apps` 标“只本机”并给出 `acornfox open 应用名`。`live_seq` 是正在服务的是第几版（列表里也有，列表不带完整的 `live`；控制台“我的应用”卡片按它写“第 N 版”，没有上线版本时写“第 N 版部署中”“还没有上线的版本”或“还没部署”）。详情里 `services`（v0.6.0 起，从应用中心装、清单写了需要的服务的应用才有）：每个需要一条，`use`、`kind`、`kind_label`、`required`、`service`（接的哪条服务，没接上是空串）、`status`、`status_label`（那条服务现在的状态，没接上是 `not_connected`；这里不跑就绪检查，所以不会是 `not_ready`，应用详情要常读、不等提供方的检查；那条服务现在还能不能用看 `GET /v1/services`）；`status 应用名` 的人读输出在“它用的服务”下每个需要一行，`--json` 的 `services` 和接口一样（没有时是空数组）。`status 应用名` 的 `--json` 另带 `open_hint`（有时才有，和 `apps` 里这个应用的一样）；`port` 是应用在容器里听的端口，不是访问地址的端口：`--json` 里同一个数另叫 `container_port`，并带一句 `port_note` 说明，人读输出写成“容器内端口”，只本机能打开的另有一行“怎么打开”（和 `apps` 的说法一样）。用旧格式（第 2 版及更早）清单装的应用（存的清单是旧格式，或者旧版本装的、没存清单但存的参数是这种应用的），详情另带 `legacy_note`：一句直接给用户看的说明（照常运行、不接服务、等它按新格式重新上架后删了重装才能用新功能），`status 应用名` 的人读输出和 `--json` 都带它，控制台应用详情的概览页原样显示成一条提示；别的应用没有这个字段 | `GET /v1/apps`、`GET /v1/apps/{app}`、`GET /v1/status` | `status [应用名 \| 部署编号]`（参数按应用名解析，和 `logs`、`rollback`、`delete` 同一规则；12 位 0-9、a-f 的写法是部署编号，同时也是合法应用名时先按应用查、没有再按部署查；都不像时报用法错误；应用不存在报 `not_found` 并提示 `acornfox apps`）、`apps`、`delete 应用名 [--volumes]`（不写应用名时用当前目录对应的应用） | 只读（`delete` 是写操作，要用户同意） |
| 部署诊断 | 最近一次部署为什么失败、怎么办 | `GET /v1/deployments/{id}`、`GET /v1/apps/{app}/deployments` | `diagnose` | 只读 |
| 启停 | 停止、启动、重启应用。命令行默认等到观察状态变了才返回：`stop` 等到 stopped（30 秒没停下说明仍在停止中），`start`、`restart` 等到 running（60 秒没起来报 `start_timeout`、退出码 1；应用没有上线过的版本报 `no_deployment`；等待被打断报 `cancelled`），所以返回后 `apps` 看到的就是新状态；`--json` 输出带 `waited`、`observed_state`，`restart` 另外照旧带 `"restarted":true`（`--no-wait` 时也带）；等待中按 Ctrl-C 或 SSH 断开（哪怕正在查询）报 `cancelled`，请求已经提交，不用再提交一次 | `POST /v1/apps/{app}/stop`、`/start`、`/restart`；等待时轮询 `GET /v1/apps/{app}` | `stop`、`start`、`restart`，都是 `[应用名] [--no-wait]`（写了应用名又写 `--app` 时两者要一致；`--no-wait` 只提交） | 会改数据 |
| 删除应用 | 删除应用，默认保留数据。从应用中心装、接着别的应用提供的服务的应用：带 `--volumes` 时按提供方清单的 `revoke` 步骤收回发给它的凭据，清单写了 `purge` 的（数据库这类）再照它删掉给它建的库或数据（收回没成功也照样试），再删接入记录；收不回、删不掉的在返回的 `warnings` 里提醒（`CAT-INST-35`，写明到哪个应用里手工删什么）。保留数据时接入记录、凭据和提供方里的库都留着，供接上旧数据重装时核对。它提供的服务还有装着的应用在用时拒绝删除（`app_in_use`，列出是哪些应用）；没人用时，带 `--volumes` 连它提供的服务一起删，保留数据时服务留着、状态变成“提供它的应用已删” | `DELETE /v1/apps/{app}` | `delete [--volumes]` | 会删数据（带 `--volumes` 时） |
| 日志 | 应用最近的日志，可以跟随；也能看某一版的运行日志（容器删除前保存，最多 1 MB）和构建日志（最多 512 KB）。每个应用保留最近 20 次部署的日志，当前版本、能回退的版本和最近一次失败的一直保留；返回前按当前密钥规则再脱敏一遍 | `GET /v1/apps/{app}/logs`、`/log-batch`、`GET /v1/deployments/{id}/logs?kind=run\|build&tail=N` | `logs [APP] [-f]`、`logs [APP] --version N [--build]` | 只读 |

| 应用资源历史（v0.5.1 开发中） | 一个应用近 1 小时、24 小时的 CPU、内存（控制台应用概览页的两张小图用）。规则和整机资源历史一样：后台服务每 30 秒记一次，只存在内存里，最多 24 小时，服务重启（包括升级）后从头记（`since` 是这个应用最早一个点）；1 小时给原始点，24 小时给 5 分钟平均；没有 7 天。应用停着的时候不记（图上是缺口），应用删除后历史一起丢掉；最多记 64 个应用。没有历史的服务端 `ranges` 为空 | `GET /v1/metrics/apps/{app}/history?range=1h\|24h`（`range` 不对回 400 `invalid_range`，应用名不合法 400 `invalid_app`，应用不存在 404） | `stats 应用 --history 1h\|24h`（摘要：点数、内存最低/平均/最高、CPU 平均/最高；`--json` 给全部的点） | 只读 |

## 已知缺口

- v0.4.0 只发 Linux 服务端和 Linux、Mac 命令行：表中标“v0.4.0 未开放”的本机安装、准备运行环境、本机服务、经网关下载运行环境，在 Mac 上返回 `SETUP-MAC-01`（`install`、`serve`、`doctor` 被拦下），Windows 不发程序；`uninstall` 仍可用，给早先在 Mac 上试装过的人清理开机自启；代码保留，用 `-tags acornfox_maclocal` 编译可打开 Mac 本机模式。

- `--json` 输出还没有 `schema_version` 字段；加之前要考虑已发布版本的兼容性。新命令遇到旧服务器时靠 `GET /v1/status` 的 `features` 判断，缺了就报 `server_too_old`（退出码 1）。
- 新控制台已用上版本记录的新字段、指定版本回退和旧版本日志；旧控制台已去掉。首页看板只放有数据来源的图表：网络流量、磁盘占用分类、7 天和热力图、下载源测速、访问量、出错次数、在线率没有接口，不在可选列表里（见 `acornfox/web/console/README.md`）；设置里没有提醒和账号分区。
- 还没有机器可读的命令清单（相当于 `commands --json`），也没有测试检查本清单和路由是否一致。
- 应用中心：后端、CLI、Skill 已有（从目录安装、浏览、同步），新控制台的页面已有；“找专人部署”的按钮前端已留好（`GET /v1/catalog` 带 `expert` 才显示），但服务端和目录格式还没有这个字段，接到哪里也没定，所以现在不显示；程序内置了两把受信公钥（正在用的和离线备用的），在线目录验签通过就用，序号不比本地新的不收；多容器应用、升级还没做；私有目录（W10）的后端、CLI、Skill 和控制台都有了（控制台按来源 + id 区分同 id 的公共、私有应用，详情和安装带 `catalog`）。删除一个还有应用接着它的服务的应用会在一开始被拒（`app_in_use`），要先删用它的应用。镜像经下载网关下发要清单里有 `artifact_sha256`。v0.6.0 起清单格式是第 3 版，目录里还是第 2 版的应用要按新格式重新上架后才能装；程序内置的目录快照现在是一份没有应用的空目录（只有服务类型定义，序号 4，比最后一份旧格式的目录大，所以旧目录不会同步盖过它），发版前要按重新上架后的目录重新生成。
