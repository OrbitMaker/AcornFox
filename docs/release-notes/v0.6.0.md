# AcornFox v0.6.0 发行说明

## 这一版是什么

这一版改的是应用中心的底子，和安装、升级的入口：

- **服务**：应用要用的东西（例如大模型接口、发信邮箱、数据库）和应用装好后能提供的东西，都登记成“服务”，装应用时自动接上；你自己已有的登记一次，以后装的应用都能用。装之前可以先看**计划**。
- **数据库和缓存成了普通应用**：PostgreSQL、MySQL、Redis 这类可以像别的应用一样在目录里上架，装好后只在内部网络给别的应用用，每个应用一个单独的库和账号。
- **应用地址算对了**：绑了域名就是 `https://域名`；装的时候就能定对外方式（`--expose`），应用拿到的地址一开始就对。
- **入口代理换成自己的容器** `acornfox-edge`：所有应用网址前面的那一层，第一次升级时会换一次（见下面“升级前请看”）。
- **国内装得更快**：装 Docker、换软件源时当场测速选最快的源；拉镜像先测每个镜像源，慢了自动换源，慢网络上也不会 10 分钟就判失败。
- **安装、升级只有一种命令**：都经引导脚本 `get.sh`，脚本和程序一定来自同一个版本。

谁需要升级：用 AcornFox 部署自己项目的，升级后照常用；想用上面这些新功能的，升级到这一版。在 v0.5.1 及更早版本上，用新的升级命令（按服务器所在网络选一条）：

```bash
# 中国大陆
curl -fsSL https://gitee.com/VIP13390/AcornFox/raw/main/get.sh | sudo bash -s -- upgrade
# 其他地区
curl -fsSL https://github.com/OrbitMaker/AcornFox/releases/latest/download/get.sh | sudo bash -s -- upgrade
```

## 升级前请看（已知影响）

- **这一版只装新格式的应用清单。** 应用目录已按新格式发布，联网的机器升级后会自动取到（想马上看到就运行 `acornfox catalog sync`）。以前按旧格式上架的应用，要等按新格式重新上架后才能再装：列表里这样的应用标着“这是旧格式的清单，这一版装不了，等这个应用按新格式重新上架”。**已经装好的应用不受影响**，照常运行，能启动、停止、删除。应用中心里现在有哪些应用，以 `acornfox catalog list` 和控制台里看到的为准。程序自带的目录里没有应用：一次都没同步到新目录的机器（例如连不上外网），应用中心是空的，装应用时会说“应用中心现在还没有可以安装的应用，要等应用按新格式重新上架”，能联网后运行 `acornfox catalog sync`（或者等每天的自动同步）就好。
- **安装、升级的一行命令换了。** 以后只用 `get.sh` 那一种（见下面“安装”“从 v0.5.1 升级”）。以前直接读 Gitee 仓库主分支上 `scripts/install/install.sh`、`upgrade.sh`、`install-cli.sh` 的命令，这一版起会停下，报 `INSTALL-SRC-01` 并打印新的命令，不改动系统。
- **第一次升到这一版时会换一次入口容器**：新的入口和原来的同时起来，新的健康了才平稳停掉原来的，接着用原来的证书，不重签。新建的访问不受影响；**已经连着的长连接、超过 8 秒还没做完的请求和 WebSocket 会断一次**，客户端重连就好。请避开访问高峰。
- 升级时 AcornFox 服务停几秒（约 4 秒），这几秒**公网控制台打不开**（以前的版本也是这样），应用不受影响。
- 新入口没起来时，原来的入口一直在服务，升级脚本按升级失败自动恢复到升级前（`EDGE-05`）。入口镜像在**停服务之前**就准备好；下载、校验、导入不成功就停下，什么都不改（`EDGE-02`）。
- **现在装的是 v0.3.x 的，要先升到 v0.5.1**：升级命令后面加 `--version v0.5.1`（`… | sudo bash -s -- upgrade --version v0.5.1`），成功后再运行一次不带 `--version` 的升级命令。直接升会在停服务之前停下（`UPGRADE-OLD-01`）。v0.4.0 及以后的版本可以直接升。
- **以前装好的应用不接服务**：它们是用旧格式的清单装的，照常运行，但 `status` 里没有“它用的服务”，自检也不查它们。要用新功能，等目录里有了它的新格式版本，删掉（默认保留数据）再用 `--reuse-data` 装回来，不急可以不动。
- **安装命令去掉了几个参数**：`acornfox install` 的 `--llm`、`--set llm.…` 没有了（大模型接口现在是一种服务，见下面“服务”）；服务器安装脚本的 `--skip-caddy` 没有了，还写着它会报“未知参数”，删掉即可。
- **慢网络上一次安装可能更久**：拉镜像不再 10 分钟就判超时，还在往下走就一直等（一个镜像所有源加起来最多 50 分钟），而且不算进整次安装的 60 分钟。好处是慢网络上大镜像也能装成，代价是一次安装最长可能要一两个小时。
- `sudo acornfox doctor`、`acornfox sources --probe` 测镜像源快慢用的镜像换成了 `nginx:1.27-alpine`，测出的数字和以前不完全可比。

## 支持哪些平台

| 平台 | 本版提供的程序 | 说明 |
| --- | --- | --- |
| Linux x86_64（amd64） | 服务端 + 命令行 | 正式支持。Ubuntu 22.04、24.04，Debian 12、13；推荐 Ubuntu 24.04 或 Debian 13 |
| Linux arm64 | 服务端 + 命令行 | 安装脚本允许安装，但**还没有实测** |
| macOS（Apple 芯片、Intel） | 只有命令行 | 在 Mac 上装命令行，经 SSH 管理 Linux 服务器。本版不提供在 Mac 本机运行 AcornFox 服务端（`SETUP-MAC-01`） |
| Windows | 不提供 | 用 SSH 登录服务器，在服务器上运行 `acornfox`，做法见 [使用手册](../user-guide.md#windows-电脑经-ssh-在服务器上操作) |

建议配置：2 核 2 GB 以上；需要 root 或 sudo。

## 安装

在 Linux 服务器上运行（按服务器所在网络选一条）：

```bash
# 中国大陆
curl -fsSL https://gitee.com/VIP13390/AcornFox/raw/main/get.sh | sudo bash
# 其他地区
curl -fsSL https://github.com/OrbitMaker/AcornFox/releases/latest/download/get.sh | sudo bash
```

在自己的电脑（Mac、Linux）上装命令行：

```bash
# 中国大陆
curl -fsSL https://gitee.com/VIP13390/AcornFox/raw/main/get.sh | bash -s -- cli
# 其他地区
curl -fsSL https://github.com/OrbitMaker/AcornFox/releases/latest/download/get.sh | bash -s -- cli
```

- 其余参数照旧写在 `-s --` 后面，例如 `… | sudo bash -s -- --china --no-lan-console`。
- 指定版本：`… | sudo bash -s -- --version v0.6.0`。预发布版只有这样写明版本才会装到。
- 卸载要在终端里确认，所以先下载再运行：`curl -fsSL <上面的地址> -o get.sh && sudo bash get.sh uninstall`（连数据一起删加 `--purge`，不能恢复）。
- 服务器在局域网里（私网地址、不是云主机）时，全新安装会默认打开局域网控制台（端口 18802），和 v0.5.1 一样；不想打开加 `--no-lan-console`。

用 AI 工作台安装，把下面这句话发给它：

```text
请安装 AcornFox Skill：下载 https://acornfox.com/skill/SKILL.md ，保存为你 skills 目录下的 acornfox/SKILL.md（Claude Code 是 ~/.claude/skills，Codex 是 ~/.codex/skills），然后按这个 Skill 把当前项目部署到我的服务器。
```

### 一行命令为什么换了

以前安装脚本从仓库主分支读，程序从“最新正式版”下载，两样东西各走各的路，可能拿到新脚本配旧程序，装完的提示和程序对不上。现在：

- `get.sh` 自己不装任何东西，只去取“要装的那个版本自带的”脚本，校验后交给它。脚本和程序一定来自同一个版本。
- 发行版里的安装、升级脚本带着版本号，只处理这个版本；拿它去装别的版本，或者配别的版本的程序文件，会停下并报 `INSTALL-VER-01`。仓库里的源码脚本不能直接拿来装（`INSTALL-SRC-01`）。
- 发行版的 `SHA256SUMS` 现在覆盖全部文件（以前只有程序文件）。`get.sh` 下载脚本后先校验，不一致就不执行（`INSTALL-GET-03`）。

## 从 v0.5.1 升级

在服务器上运行（按服务器所在网络选一条）：

```bash
# 中国大陆
curl -fsSL https://gitee.com/VIP13390/AcornFox/raw/main/get.sh | sudo bash -s -- upgrade
# 其他地区
curl -fsSL https://github.com/OrbitMaker/AcornFox/releases/latest/download/get.sh | sudo bash -s -- upgrade
```

- 管道运行就视为同意升级；已经是最新版本时直接退出，不停服务。只有要重装同一版本时才加 `-y`。
- 升级前把程序和数据库备份到 `/var/lib/acornfox/backups/`（保留最近 5 份），再做数据库迁移（新增服务登记等）。应用容器一直运行，升级期间命令行和控制台会暂时连不上。
- AcornFox 只能升级，不能回到旧版本；升级没成功时自动恢复到升级前。
- 换入口容器的细节见上面“升级前请看”。换好后脚本按切换记录（`/var/lib/acornfox/edge-switch.json`）删掉原来的入口容器和它用过、新入口不用的设置卷。确认入口换好最多等 120 秒，环境变量 `EDGE_SWITCH_WAIT` 可改；升级失败恢复时换不回原来的入口报 `EDGE-06`，`acornfox faults EDGE-06` 有手工步骤。
- 已经装好的机器升级后，`/etc/docker/daemon.json` 不会被改；里面有不能用的加速地址时，`sudo acornfox doctor` 会提醒（`SETUP-NET-03`）。
- 先升级服务器，再升级自己电脑上的命令行（重新运行一次装命令行的命令）。`services`、`install --plan`、`install --expose` 这些新命令要服务器也是 v0.6.0。
- 给 AI 工作台用的 Skill：升级命令行后运行一次 `acornfox skill install` 换成新版。

## 新功能和改进

### 服务：应用要用的东西登记一次

有的应用要用到别的东西才能完整工作，例如要调大模型的应用需要一个“大模型接口”，要发通知的应用需要一个“邮箱（发信）”。以前只对大模型做了专门的处理；现在所有这类东西都按同一套办法来：

- 每个应用写明它**需要的服务**（必须的，或者可选的：可选的没有也能装，只是少一部分功能）和装好后**能提供的服务**。提供服务的应用装好就自动登记。
- 你自己已有的东西（自建的邮箱服务器、别家的大模型 Key）可以登记进来，以后装的应用都能用：

  ```bash
  acornfox services kinds                   # 有哪些服务类型，每种有哪几项
  acornfox services add smtp --name 我的邮箱 --set host=mail.example.com --set username=me --set password=-
  acornfox services test 我的邮箱           # 试一下通不通
  acornfox services list                    # 这台机器上的服务、状态、谁在用
  ```

- 密码、Key 写成 `项=-`，命令会让你输入，不会留在命令历史里。也可以在控制台“设置 → 服务”里登记。所有输出里密码和 Key 只显示后 4 位。
- 装应用时按服务类型自动接上：正好一条就用它；有好几条让你选一条（`--use 需要名=服务名`）；可选的没有就跳过；必须的没有就停下，告诉你怎么登记一条。
- AcornFox 不会替你去装别的应用来提供服务，也不会提示先装哪个应用。几个应用要一起装好并接上，装**配方**（目录里发布好的套装：装哪几个应用、按什么顺序、谁接谁）。
- 一个应用接上另一个应用提供的服务时，要给它单独发的凭据（例如一把令牌），由 AcornFox 照应用清单里写的步骤去做；连数据一起删掉使用方时自动收回，收不回的会告诉你到哪里手工删（`CAT-INST-35`）。
- 删提供服务的应用：保留数据删除（默认）时这条服务还在，状态显示“提供它的应用已删”，用旧数据把应用装回来就又能用；连数据一起删（`--volumes`）时服务才跟着没了。还有装着的应用接着它的服务时删不掉，会告诉你是哪些应用。
- 装应用时的保密设置项也可以从键盘输入：`acornfox install 应用 --set 设置项=-`，命令从键盘读一行当它的值（有几个就按出现的顺序读几行）。只看计划（`--plan`）时不读；不是保密的设置项，`-` 就是值本身。

### 装之前先看计划

```bash
acornfox install 应用 --plan
acornfox install --recipe 配方 --plan
```

只看，什么都不装。它列出：需要的每一种服务现在怎样（已接上哪条、可选的没有先跳过、必须的没有、有好几条要选一条）；必须的没有时怎么办（给出登记一条的命令，照抄就能用；同类的服务只是现在用不了的，给出让它能用的命令）；还有哪些必填参数没填；装不了的原因。控制台的安装弹窗里同样有“需要的服务”一块，没有的可以当场登记。

### 数据库和缓存成了普通应用

以前 AcornFox 只在程序里认识 PostgreSQL、MySQL、Redis，给你自己部署的项目用。现在它们也可以是应用中心里的普通应用，和别的应用一样上架、安装、删除（目录里有的才能装）。怎么给一个应用开库、开账号、核对、删掉，都写在数据库应用自己的清单里，AcornFox 照着在它的容器里执行；密码只走环境变量和标准输入，不出现在命令行参数、进程列表、日志和输出里。

- **只在内部网络**：数据库、缓存这类应用装好后不映射你能访问的端口，没有网页和访问地址，`acornfox apps`、`status` 写“只在内部网络，给别的应用用”；`acornfox open` 打不开它（`OPEN-APP-03`），也不能改对外方式、绑域名。别的应用在内部网络里按它的名字连它。
- **每个应用一个库**：一个数据库应用可以给好几个应用用，每个应用有自己的库和只能用这个库的账号，密码随机生成，互相看不到。
- **独占和接满**：应用可以要求独占一条服务，提供方也可以限制同时接几个应用。接不了时计划里写明被谁占着，`--use` 指定这样一条时报 `CAT-INST-38`；`acornfox services list` 写“被应用 … 独占”“还能接 N 个”“已经接满”。
- **删数据分开**：保留数据删除一个应用时，给它开的库和账号都留着，装回来接着用；连数据一起删（`--volumes`）时库也一起删，删不掉会提醒你到哪里手工删（`CAT-INST-35`）。接的是你自己登记的数据库时，那边的库不会被动。
- **核对不过就停下**：接旧数据重装时，原来的数据库账号核对不过（例如你在数据库里改过它的密码），这次安装停下（`CAT-INST-37`），不会悄悄换一个空库；看计划时就会先核对一次。
- **就绪检查**：提供服务的应用可以写一个只读的检查，说明它什么时候才算能用（例如还没配上游）。没通过时服务状态是“还不能用”加它写的原因，`services list`、安装计划和 `acornfox doctor`（`CAT-SVC-09`）都会照原话告诉你；这不挡安装。
- **`acornfox add postgres|mysql|redis` 不变**：给你自己部署的项目加数据库，用法和以前一样，已经加好的数据库照常用。

### 应用地址和对外方式

- **应用地址只在一处算**：平台变量 `app.url`、`acornfox status`、`acornfox apps`、安装结果和首次登录信息里的地址都一样。绑了域名是 `https://域名`（最早绑的那个）；没绑就按对外方式取本机地址、服务器地址加端口；只在内部网络的应用没有地址。以前 `app.url` 几乎总是 `http://127.0.0.1:端口`，绑了域名也不变。
- **装的时候就定对外方式**：`acornfox install 应用 --expose local|lan|public`。规则和 `acornfox app set --expose` 一样；配方里对这次要装的应用都生效；写错报 `CAT-INST-02`，什么都不建。
- **地址是装的时候写进应用的**：装好以后再改对外方式、绑域名，这一版不会去改已经写进应用的地址（例如应用自己生成的 webhook 地址），应用照常运行。`acornfox apps vars 应用` 的平台变量多了“现在的值”；和装时不一样、应用又用到它时标 `APP-VARS-01`，并写着怎么办。
- 只本机的应用绑了域名以后，不再提示“只在服务器本机能打开”。

### 国内安装和拉镜像

- **装 Docker、换系统软件源**：对几家国内镜像站当场各取一小段测快慢（整个最多约 15 秒），用能用而且最快的；以前固定先用一家，家庭宽带上可能很慢。从镜像站取到的 Docker 签名密钥会核对是不是 Docker 官方的那一把，不是就换下一个源：装上的 Docker 一定是官方签名的。都不能用时报 `INSTALL-DOCKER-01`。
- **拉镜像前先测每个镜像源**：拒绝访问、没有这个镜像、限流、连不上的跳过，慢的排到后面；拉的过程中太慢会换下一个源。新加一个公共镜像源 `dockerproxy.net`，只当兜底：固定排在最后，别的源都不能用或太慢时才用它（它的运营方没有公开说明是谁）。
- **拉镜像不再 10 分钟就判超时**（见上面“升级前请看”）。没拉成时，报错逐个写出每个源怎么了（`CAT-INST-12`）。
- **安装进度写清在拉什么**：正在拉哪个镜像、从哪个源（第几个、共几个）、拉到多少、最近多快、拉了多久，换过源的写上前一个源怎么了（`acornfox install status`、控制台都看得到）。Docker 不报进度时如实写“看不到拉到多少”，不编数字。
- **新命令 `acornfox sources`**：这台机器拉镜像用哪些源、按什么先后；`--probe` 现在就测一遍每个源。
- Docker 的镜像加速地址（`/etc/docker/daemon.json`）改由程序给出，安装脚本里不再写死。`sudo acornfox doctor` 多两项：镜像下载源（现在先用哪个、多快）、Docker 的镜像加速配置；有源不能用或很慢时提醒（`SETUP-NET-03`）。

### 入口代理换成自己的容器

所有应用的网址、绑定的域名、公网控制台都经过一个入口代理。以前它是一个直接跑 Caddy 的容器（`acornfox-caddy`）；这一版换成 `acornfox-edge`：里面是上游原版 Caddy 2.8.4，加一个管它的小程序 `afx-edge`，AcornFox 主程序只通过一个通用接口给它交设置。

- 入口代理重启以后自己把上次的设置装回去，不用等主程序。
- 入口镜像不从镜像仓库拉：发行版里带入口包（见下面“发行文件”），安装和升级脚本下载、校验后导入。程序要哪个入口版本：`acornfox version --edge`（这一版是 `2.8.4-1`）。只有 Caddy 或 `afx-edge` 变了才换入口版本，以后平台升级一般不碰入口容器。
- 管理口从 `127.0.0.1:18808` 改成 `127.0.0.1:18807`，令牌文件改名 `edge-admin.token`；安装和升级前的端口检查跟着改成 18807。
- 查它：`sudo acornfox doctor` 的“入口代理”一项（`EDGE-01` 没在运行、`EDGE-02` 入口镜像缺失、`EDGE-03` 管理口不应答或拒绝令牌、`EDGE-04` 设置没生效）；`sudo docker logs --tail 50 acornfox-edge`；`sudo docker exec acornfox-edge /usr/bin/afx-edge health`。
- 卸载时 `--purge` 一起删掉入口容器的卷。

### 自检

- `acornfox doctor` 和控制台“运行环境”页新增“应用用的服务”（`CAT-SVC-08`）：已装的应用接着的服务现在不能用时（提供它的应用停着或已删、还差必填项）给一条提醒，写明是哪个应用接的哪条服务、怎么办；服务的就绪检查没通过时另给一条（`CAT-SVC-09`）。都只是提醒，应用照常运行。
- `acornfox status 应用名` 也列出“它用的服务”：每个需要接的哪条服务、现在能不能用。

### 行为变化

- 应用装好后的初始化没做成，这次安装就算失败并清理（以前有的情况只提示、照常装完）。
- 安装没成功时，平台收回这次发出去的凭据，并删掉这次在数据库里新建的库（只删这次新建的；接上旧数据重装时原来的库不会动）；没删掉的，任务里会提醒你（`CAT-INST-35`）。
- 接上旧数据重装时，发给它的旧凭据要先核对；没通过就换一份新的并告诉你。数据库这类写明了“核对不过就停下”的除外（`CAT-INST-37`）。
- 应用回“请求太多”时，报错直接说“这个应用限制了请求次数，过一会儿再试”，不自动重发。
- 运行器在拉镜像的时限过后还没回话时，报错写明是运行器没回话、怎么查，不再只有一句“runner: unavailable”。

## 去掉的东西

- 安装命令的 `--llm` 参数，以及 `--set llm.base_url=…`、`--set llm.api_key=…`、`--set llm.model=…`。大模型接口现在是一种普通的服务：登记一条你自己的（`acornfox services add llm_gateway …`，Key 写成 `api_key=-`），或者由装好的、能提供大模型接口的应用提供。
- 三个大模型平台变量（默认对话模型、平台模型接口地址、平台 Key）。模型名这类随应用变的，是应用自己的参数，安装时填。加上新加的两个，平台变量现在是 7 个：时区、网络区域、两个下载源、应用访问地址 `app.url`、访问方式 `app.scheme`（`http` 或 `https`）、访问地址里的主机 `app.host`。
- 以前为某个具体应用写在程序里的专门处理都拿掉了：平台不认识任何具体的应用，应用要做的初始化、发凭据、收回，都写在应用自己的清单里。
- 服务器安装脚本的 `--skip-caddy`；后台服务的启动参数 `-edge off`、`-caddy-admin`；从 v0.3.x 直接升级的路径（要先升到 v0.5.1）。
- 发行版里不再单独附带上游的 Caddy 安装包，改成两个入口包。
- 接口：安装请求（`POST /v1/catalog/install`）没有 `llm` 字段了，改用 `use`；应用详情（`GET /v1/catalog/apps/{id}`）不再给“大模型来源能不能用”，改给 `uses`、`provides_detail`。公网控制台接口的错误码 `caddy_unavailable` 改名 `edge_unavailable`（命令行和页面显示的是服务端给的说明文字，不受影响）。
- 停用的故障编号：`CAT-INST-09`、`CAT-INST-10`、`CAT-INST-11`（以前平台内置的大模型来源出的错）。编号保留，不会再分给别的错误；同类问题现在报 `CAT-INST-31`～`35`。

## 新的故障编号

每个编号的说明用 `acornfox faults 编号` 查。

- 安装入口：`INSTALL-VER-01`（脚本和要装的版本不是同一个）、`INSTALL-SRC-01`（直接运行了源码仓库里的脚本）、`INSTALL-GET-01`～`04`（引导脚本查不到版本、下载失败、校验不过、用法不对）。
- 国内安装：`INSTALL-DOCKER-01`（装 Docker 的软件源都不能用）、`SETUP-NET-03`（有镜像源不能用或很慢，或 daemon.json 里有不能用的加速地址；只提醒）。
- 升级和入口代理：`UPGRADE-OLD-01`（现在装的是 v0.3.x，要先升到 v0.5.1）、`EDGE-01`～`06`（没在运行、入口镜像缺失、管理口不应答或拒绝令牌、设置没生效、升级时换入口没成功、恢复时没能换回原来的入口）。
- 应用中心：`CAT-INST-31`～`35`（缺服务、要选一条、指定的服务不对、发凭据没成、收回或删库没成）、`CAT-INST-36`（清单是旧格式的，这一版装不了）、`CAT-INST-37`（原来的凭据核对没过，按清单停下了）、`CAT-INST-38`（要接的服务被占着或已经接满）、`CAT-INST-39`（清单里的一个值算不出来，安装已失败并清理）、`CAT-SVC-01`～`09`（登记、改、删、试连服务时的问题，自检里的“应用用的服务不可用”“服务还不能用”）、`OPEN-APP-03`（应用只在内部网络，没有网页可以打开）、`APP-VARS-01`（应用装时算的平台变量和现在的不一样，只提醒）。
- 给目录维护者：`CAT-LINT-22`～`51`（见下面）。

## 给写应用清单的人

- 清单格式是第 3 版（`schema: 3`），第 2 版的写法都删了，旧清单要按新格式重写。这些写法从 0.6.0 起有。
- **需要和提供**：应用写 `uses`（需要的服务：名字、服务类型、是不是可选、没有时会怎样）和 `provides`（能提供的服务：每一项怎么来，平台算、给每个使用方单独发、或者要用户在应用里做一步；发凭据、收回、核对的步骤）。服务类型定义放在目录仓库的 `service-types/`，一种一个文件，打包时并进 `index.json` 的 `service_types`。
- **步骤**（`init`，以及 `provides` 的 `issue`、`revoke`、`check`）共用一种写法：只读的 `GET` 步骤可以写重试；收回可以写“已经没了算成功”（`finish_if`）；每次发凭据带一个随机编号（`{{issue.id}}`）；步骤也可以是在应用自己的容器里执行一条命令（`exec`），保密值只走 `env` 和 `stdin`。
- **数据库这类服务**：`dedicated`（只接没有别的应用在用的服务）、`max_consumers`（限制同时接几个）、`purge`（连数据一起删时删掉给它建的库）、`on_check_fail: stop`（接旧数据重装时账号核对不过就停下）、`ready`（就绪检查，不挡安装）；`issue_vars` 在发凭据前生成每个使用方自己的随机密码这类值，`values` 的模板可以引用 `issued.*` 拼出每个使用方自己的连接串。
- **不说 HTTP 的应用**：入口可以是 `tcp`；健康检查除了 `path`，还可以写 `exec`（可再要求输出等于 `expect_stdout`）或 `tcp: true`；访问方式加 `internal`（只在内部网络，主入口是 `tcp` 的应用只能用它）。
- **值的写法**：`{{种类.名字}}`，后面可以用竖线接变换：`{{种类.名字 | 变换 "参数"}}`，参数一律用双引号。变换固定 11 种：`default`、`urlencode`、`b64`、`json`、`yaml`、`shell`、`lower`、`upper`、`replace`、`map`（参数写成 `"键=值"`，`"*=值"` 兜底；没对上又没兜底，安装失败 `CAT-INST-39`）、`sha256`。例如 `'{{platform.app.scheme | map "https=true" "*=false"}}'`。
- **能写值的地方**：配置文件模板、环境变量的 `value`、启动命令 `container.command` 的每一项（一项算成一个参数，不经过命令行解释；不能引用保密的值）、首次登录的 `value`。环境变量的 `from` 仍只取一个引用、不带变换；写了 `optional: true` 的环境变量，算出来是空的整条不写。
- **按条件写**：环境变量的一条、配置文件的一个文件可以写 `if`，只认三种：`'引用'`（有值且不是 false、0、空）、`'引用 == 值'`、`'引用 != 值'`；引用没有值时不成立。同一个环境变量写几条时，每条都要带 `if`，而且要看得出两两不会同时成立。按网络区域给不同的值写 `if: 'platform.region == cn'`（格式里的 `cn` 删了，程序从来没读过它）。
- **只替换平台的引用**：以 `params.`、`platform.`、`uses.`、`self.`、`saved.`、`issued.`、`consumer.`、`issue.` 开头的 `{{…}}` 才替换，别的 `{{…}}` 原样保留（检查给提醒 `CAT-LINT-51`）；`\{{` 写出字面的 `{{`。
- **检查**：`acornfox catalog lint` 新增 `CAT-LINT-22`～`51`（服务类型和项、步骤、执行命令、入口和健康检查、独占和删数据、就绪检查、值的写法、`if`、启动命令里的保密值等）。`acornfox catalog vars` 的报告多了“需要什么服务”“能提供什么服务”两张表，变量只分五类：系统给、平台生成、有默认值、可选、必须用户填；指纹算法升到第 2 版（按第 1 版确认过的上架记录要重新确认）。
- 给别的程序读平台变量整张表：`acornfox --json catalog platform-vars --offline`，每个变量带什么时候算（`refresh`）、哪些版本有值（`editions`）、能改的值要符合什么（`rule`、`rule_label`）；`GET /v1/catalog/platform-vars` 和应用详情的 `platform` 里也有。`acornfox apps vars 应用 --json` 多了 `env`：写进应用的每个环境变量算好以后的值（保密的遮住，给 `sha256` 指纹）。

## 给 AI 工作台

Skill 已经跟着改了，用 `acornfox skill install` 更新。要点：

- 装应用先看计划（`install 应用 --plan`），按“需要的服务”的四种状态照固定步骤做。缺必须的服务时照计划给的命令做（启动提供它的应用、填上还差的项、用旧数据把已删的提供方装回来，都先问用户）；都不是就问用户有没有现成的，有就让用户自己登记（密码和 Key 由用户自己输入），没有就停下，不去装别的应用。需要数据库时同样只问用户有没有现成的。
- 用户要在局域网里用的应用，装之前先问用户，同意后装的时候就加 `--expose lan`；装完才开放的，告诉用户 webhook 这类地址这一版不会跟着改（`APP-VARS-01`）。
- 只在内部网络的应用装好后不叫用户打开；接旧数据重装时数据库账号核对不过就停下，把选择交给用户。
- 应用中心是空的时（例如这台机器还没同步到新目录），照实告诉用户，不换别的办法装、不降级。
- 自检和排查入口代理看 `acornfox-edge` 和 `EDGE-01`～`06`。

## 已知限制

- **应用中心**：程序自带的目录里没有应用，一次都没同步到新目录的机器上应用中心是空的；以前按旧格式上架的应用要等按新格式重新上架后才能再装（见“升级前请看”）。
- **用旧格式清单装的应用**：不接服务；以前在别的应用里拿过凭据的（例如接本机模型网关的），删除时平台不再替它收回那份凭据，删除结果里会提醒（`CAT-INST-35`），要你到那个应用里自己看一下。
- **应用升级**：还没有把已装的应用升级到目录里新版本的功能。换版本用“删除（保留数据）→ 加 `--reuse-data` 重装”；新版本能不能读旧数据由应用自己决定，重要的数据请先自己备份。
- **装好后改设置**：还不能改，`acornfox apps vars` 只能看；改了对外方式、绑了域名，已经写进应用的地址不会跟着改（`APP-VARS-01`）。
- **保留了数据、后来不想要了**：还没有删除这类旧数据卷的命令，要用 `docker volume rm` 删（卷名在 `CAT-INST-24` 的错误里）。
- **慢网络上的安装时间**：一次安装最长可能要一两个小时（见“升级前请看”）；“比平常慢”“卡住”的提示只是提醒，不会取消安装。
- **局域网控制台**：页面上还不能改密码，要在服务器上 `acornfox lan-console reset-password` 后在浏览器里重设；局域网里是明文 HTTP。
- **镜像还没拉完时删附加服务**：刚 `acornfox add redis`（或 postgres、mysql）、镜像还没拉完就 `acornfox remove redis`，命令先返回“已删除”，容器要等镜像拉完、建出来后再过几秒才真删掉。最终状态是对的。
- **私有目录**：这一版不开放。
- **资源历史**：整机和应用的资源历史只存在内存里，最多 24 小时，后台服务重启后重新记。
- **arm64 Linux**：程序和入口包照常发布，安装脚本也允许，但还没在真的 arm64 机器上实测过。
- **Windows、Mac 本机运行**：本版不提供，Mac 上只能装命令行；Mac 命令行没有 Apple 开发者签名，用安装命令装不会被 Gatekeeper 拦，自己用浏览器下载程序时可能会被拦。
- **离线安装**（自己下载程序文件，用 `--binary`）时，脚本、程序文件和入口包要取自同一个发行版；入口包放在程序文件旁边，或用 `--edge-package 文件` 指定。
- 用 `--version` 装 v0.6.0 之前的版本时，那些版本的发行版没有给脚本提供校验值，`get.sh` 会提示一句，照常继续。

## 联网和隐私

AcornFox 没有使用统计，也没有崩溃上报。这一版没有新增要联系的 AcornFox 服务器；下载网关、应用目录同步、自检时向下载网关发的 HEAD 请求，和 v0.5.1 一样。变了的是这几处，都不经过我们的服务器：

- **入口包**：安装、升级时本机还没有这个版本的入口镜像，就和程序一样从发行版下载（中国大陆先 Gitee，再 GitHub），按同一版本的 `SHA256SUMS` 校验。
- **软件源测速**：装 Docker、换系统软件源前，对候选的几家国内镜像站各取一小段测快慢。
- **镜像源**：国内拉镜像前对表里的每个源取一次镜像清单和一段镜像层测快慢；表里多了 `dockerproxy.net`（只当兜底）。`sudo acornfox doctor`、`acornfox sources --probe` 用 `nginx:1.27-alpine` 测，每个源最多取 16 MB。
- **你登记的服务**：`acornfox services test` 会从服务器去连你登记的地址（邮箱、数据库这类只试能不能连上；大模型接口发一次带你的 Key 的请求）；接上它的应用会去访问它。

具体访问哪些地址、什么时候、怎么关，见 [使用手册的“隐私和联网说明”](../user-guide.md#隐私和联网说明)。
