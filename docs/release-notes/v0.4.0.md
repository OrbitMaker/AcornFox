# AcornFox v0.4.0 发行说明

## 这一版是什么

在 Linux 服务器上用一行命令装好 AcornFox，之后用命令行、网页控制台或 AI 工作台把应用部署上去。AI 工作台（Claude Code、Codex 等）只要照着官网的 AcornFox Skill 做，就能完成安装、自检和第一次部署。

## 支持哪些平台

| 平台 | 本版提供的程序 | 说明 |
| --- | --- | --- |
| Linux x86_64（amd64） | 服务端 + 命令行 | 正式支持，见下面“支持的系统” |
| Linux arm64 | 服务端 + 命令行 | 安装脚本允许安装，但**还没有实测** |
| macOS（Apple 芯片、Intel） | 只有命令行 | 在 Mac 上装命令行，经 SSH 管理 Linux 服务器。在 Mac 本机运行 AcornFox 服务端即将支持，本版在 Mac 上运行 `acornfox install`、`acornfox doctor`（以及对 Mac 本机的 `acornfox setup`）只会提示“即将支持”（故障编号 `SETUP-MAC-01`） |
| Windows | 不提供 | 做法见下面“Windows 用户怎么用” |

### 支持的系统（服务端）

| 系统 | 状态 |
| --- | --- |
| Ubuntu 24.04、Debian 13（x86_64） | 推荐。全新安装、自检、部署都实测通过 |
| Ubuntu 22.04、Debian 12（x86_64） | 支持。全新安装、自检、部署都实测通过 |
| 其他 Ubuntu、Debian 版本 | 安装脚本会停下（`INSTALL-OS-02`）；加 `--force-os` 可以继续，风险自负 |
| Alibaba Cloud Linux、OpenCloudOS、TencentOS、veLinux、CentOS、Rocky 等 | 不支持，安装脚本一开始就停下（`INSTALL-OS-01`）。买云服务器时系统请选 Ubuntu 24.04 或 Debian 13 |

建议配置：2 核 2 GB 以上；需要 root 或 sudo。从 v0.3.x 升级和回滚只在 Ubuntu 24.04 上实测过。

### 国内云主机自动用厂商内网源

安装脚本读云厂商的元数据，认出服务器在哪家云、哪个地域，然后自动选软件源，不用手动配置：

| 云厂商 | 系统软件源（APT）和 Docker 安装包 | Docker Hub 镜像加速 | 实测 |
| --- | --- | --- | --- |
| 阿里云 | 阿里云内网源 | DaoCloud、1Panel 公共加速 | 真机实测：85 秒装好 |
| 腾讯云 | 腾讯云内网源 | 大陆地域先用腾讯云内网加速，再用 DaoCloud、1Panel | 真机实测：63 秒装好，部署时镜像从内网加速拉取 |
| 火山引擎 | 火山引擎内网源 | DaoCloud、1Panel 公共加速 | 在测试机上模拟测试过 |
| 华为云 | 认出是中国大陆地域，用华为云公共镜像站 | DaoCloud、1Panel 公共加速 | 在测试机上模拟测试过 |

- 内网源连不上时自动换到公共镜像站（华为、腾讯、阿里、南京大学、清华依次尝试），不会因此装不上。
- 阿里云、腾讯云、火山引擎的境外地域（香港、新加坡等）也会先用内网源，其余按海外处理：从 GitHub 下载，不配国内镜像加速。
- 不在云上、或认不出是哪家云时，按 IP 归属地判断是否在中国大陆。判断错了可以加 `--china` 或 `--global` 指定。
- 识别结果记在服务器的 `/etc/acornfox/install.env`。
- 在家用宽带或网络较慢的机器上，安装主要花在下载 Docker 上，可能要 15～40 分钟。

## 安装

### 正式版 v0.4.0

在 Linux 服务器上运行（按服务器所在网络选一条）。

中国大陆：

```bash
curl -fsSL https://gitee.com/VIP13390/AcornFox/raw/main/scripts/install/install.sh | sudo bash
```

其他地区：

```bash
curl -fsSL https://github.com/OrbitMaker/AcornFox/releases/latest/download/install.sh | sudo bash
```

用 AI 工作台安装，把下面这句话发给它：

```text
请安装 AcornFox Skill：下载 https://acornfox.com/skill/SKILL.md ，保存为你 skills 目录下的 acornfox/SKILL.md（Claude Code 是 ~/.claude/skills，Codex 是 ~/.codex/skills），然后按这个 Skill 把当前项目部署到我的服务器。
```

装过 v0.4.0-rc.1 的服务器，用下面“从 v0.3.x 升级”里的正式版升级命令升到 v0.4.0 即可。

## Windows 用户怎么用

本版不提供 Windows 程序。服务器上装好 AcornFox 后，服务器上就有 `acornfox` 命令，直接在服务器上用：

1. 用 Windows 自带的 SSH 登录服务器（PowerShell 里运行 `ssh 用户名@服务器地址`）。AI 工作台也可以经 SSH 在服务器上执行命令。
2. 登录用户不是 root 时，先把自己加进 `acornfox-users` 组，然后退出、重新登录一次：

   ```bash
   sudo usermod -aG acornfox-users $USER
   ```

3. 在服务器上登记本机（只做一次）：

   ```bash
   acornfox target add local --url unix:///run/acornfox/api.sock
   ```

4. 部署：
   - 现成镜像和公开的 Git 仓库照常：`acornfox deploy --image nginx:1.27-alpine --port 80`、`acornfox deploy --git 仓库地址`。
   - 部署自己电脑上的项目文件夹，要先把代码放到服务器上：推到 Git 仓库后用 `--git` 部署；或者在 PowerShell 里用 `scp -r 本地文件夹 用户名@服务器地址:` 传到服务器上你的主目录，再在服务器上进入这个文件夹运行 `acornfox deploy`。

## 新功能和改进

### 安装

- **安装前检查**：在改动系统之前，先检查系统版本、CPU 架构、磁盘空间（数据盘至少 2 GB）和端口占用。不满足时停下，打印故障编号和处理办法，系统不会被改动。

  | 故障编号 | 意思 |
  | --- | --- |
  | `INSTALL-ROOT-01` | 没有用 root 或 sudo 运行 |
  | `INSTALL-OS-01` | 系统不是 Ubuntu 或 Debian |
  | `INSTALL-OS-02` | Ubuntu、Debian 版本不在支持列表（可加 `--force-os`） |
  | `INSTALL-ARCH-01` | CPU 不是 x86_64 或 arm64 |
  | `INSTALL-DISK-01` | 剩余空间不足 2 GB |
  | `INSTALL-PORT-01` | AcornFox 自己用的端口 18800、18801、18808 被占用 |
  | `INSTALL-PORT-02` | 80 或 443 被占用（例如宝塔、1Panel、Nginx）。可停掉占用的程序，或加 `--allow-busy-80-443` 共存；共存时应用照常用“服务器地址:端口”打开，但不能在 AcornFox 里绑域名、开 HTTPS 和公网控制台 |
  | `INSTALL-PORT-03` | 应用端口段 18810-18899 里有端口被占用 |

- **云主机内网源**：见上面“国内云主机自动用厂商内网源”。国内公共镜像站按家用宽带实测速度排序，华为、腾讯优先；ghcr.io 上的镜像在中国大陆走南京大学镜像。
- **装完的提示分两种情况写**：AI 工作台（或你自己）就在这台服务器上，还是在自己电脑上经 SSH 管理。普通用户登录时，提示里直接写出要执行的加组命令。
- 系统刚开机、自动更新占着软件包锁时，安装会等锁释放，不再直接失败。
- 输出不是终端时（AI 工作台、日志文件）不刷进度条，方便阅读。
- 可以用环境变量 `ACORNFOX_DOCKER_CE_MIRROR` 指定自己的 Docker 软件源（例如企业内网镜像）。
- 新增卸载脚本 `uninstall.sh`：默认保留数据，重新安装后应用和数据库还在；`--purge` 全部删除。

### 自检

- 新增 `acornfox doctor`（在服务器上运行）：检查 Docker、后台服务、磁盘空间、端口占用，每个问题带故障编号；`acornfox doctor --json` 输出 JSON，方便 AI 工作台判断。
- 按安装时记下的网络环境检查镜像下载源，海外服务器不再被误报“国内镜像源连不上”。
- 普通用户（已加入 `acornfox-users` 组）运行自检，不再误报“Docker 连不上”。

### 部署和版本

- **回退到指定版本**：`acornfox versions` 列出每一版的状态、来源、用时、失败原因，以及能不能回退；`acornfox rollback --to N` 回到第 N 版。回退只换程序，不动数据库、数据目录和环境变量。每个应用保留当前版本以外最近 5 个可回退的版本。
- **旧版本日志**：每次部署都保存运行日志和构建日志，`acornfox logs --version N` 看第 N 版的运行日志，加 `--build` 看构建日志。日志里的密钥值、网址里的账号密码会替换成 `******`。升级到本版之前部署的版本没有保存日志。
- **等部署结果的写法**：`deploy`、`redeploy`、`rollback` 默认等到上线或失败才返回（默认最多等 20 分钟，`--timeout` 可改）；加 `--no-wait` 只提交、马上返回，之后用 `acornfox status` 查结果。AI 工作台的单条命令有时间限制，Skill 里首推 `--no-wait` 加查状态。
- 等待时 SSH 断开或终端关掉，部署在服务器上照常进行；命令行会输出“已取消等待”和部署编号，不再误报 SSH 连接失败。
- `deploy --image`、`deploy --git` 现在也认 `--port`、`--health-path`。
- 构建大项目时不再把整个上传包读进内存，内存占用明显降低。

### 资源和访问

- **内存、CPU 上限**：`acornfox app set --memory 512 --cpu 1` 这样调整单个应用的上限（内存单位 MB），立即生效；`acornfox limits` 查看和设置整台服务器最多分给应用多少内存和 CPU。控制台里可以拖动滑块调整。
- **暴露方式**：`acornfox app set --expose local` 让应用只能从服务器本机打开；`public`（Linux 默认）是所有网卡都能打开、可以绑域名。
- **局域网控制台**：`acornfox lan-console enable` 在局域网里用密码打开控制台，用完 `disable`。公网服务器不建议开，要从公网管理用 `acornfox public-console enable 域名`（带 HTTPS）。
- **网关 Caddy 改成容器**：Caddy 现在作为容器 `acornfox-caddy` 运行，由 AcornFox 管理；从 v0.3.x 升级时自动从系统里的 Caddy 换过来，证书一并迁移。

### 控制台

- 多应用首页：搜索、筛选、排序，可切换列表视图。
- 需要处理的提醒集中到右上角的铃铛。
- 应用配置页用滑块调整内存、CPU 上限，概览页的资源卡片有“调整上限”入口。

### AI 工作台 Skill

- Skill 重写：较弱的模型照着做，也能从判断“装在哪台机器”开始，完成 SSH 连接（含核对服务器指纹）、安装、自检、登记服务器和第一次部署。
- 覆盖普通用户登录（例如腾讯云默认的 `ubuntu` 用户）、加组后什么时候生效、各阶段大约多久、卡住怎么判断、升级和回滚的故障编号、Caddy 警告、核对和修改应用访问地址。
- 花钱、删数据、改安全组、输入密码这些事，Skill 都要求先停下问用户。
- 已装命令行的，用 `acornfox skill install` 安装和命令行同版本的 Skill。

## 行为变化

- `acornfox redeploy` 改为默认等到上线或失败才返回。脚本里需要原来“提交就返回”的行为，加 `--no-wait`。
- 应用的内存上限最少 256 MB，新应用默认 256 MB。所有应用和数据库的内存上限加起来不能超过整机上限，用 `acornfox limits` 查看。
- 通过管道运行升级脚本（`curl … | sudo bash`，包括 AI 工作台代为执行）就视为同意升级；已经是最新版本时直接退出，不停服务。

## 从 v0.3.x 升级

### 升级命令

在服务器上运行（按服务器所在网络选一条）。

正式版，中国大陆：

```bash
curl -fsSL https://gitee.com/VIP13390/AcornFox/raw/main/scripts/install/upgrade.sh | sudo bash
```

正式版，其他地区：

```bash
curl -fsSL https://github.com/OrbitMaker/AcornFox/releases/latest/download/upgrade.sh | sudo bash
```

- 不用加 `-y`：管道运行就视为同意升级；已经是目标版本时直接退出，不停服务。`-y` 会把同一版本原地重装一遍（服务会停一下），只在确实要重装时加。
- 仓库已改名。v0.3.x 控制台里显示的中国大陆升级命令用的是旧的 Gitee 地址，已经打不开，请用上面的命令。
- 自己电脑上的命令行也请一起升级（重新运行一次安装命令行的命令）。新命令行连没升级的服务器时，`versions`、`rollback --to`、`logs --version` 会提示“服务器版本较旧，先升级”，不会执行；老命令行连新服务器，原有命令照常能用。

### 升级时会发生什么

1. 先下载新版本并按 SHA256SUMS 校验；下载失败不动现有安装。
2. 停 AcornFox 服务，把程序和数据库备份到 `/var/lib/acornfox/backups/`（保留最近 5 份），再做数据库迁移。
3. 迁移失败、或新版本服务起不来时，自动换回原来的程序和数据库。
4. **应用容器一直运行，但从 v0.3.x 升级时应用网址会断几秒**（实测 2.5～3 秒）：系统里的 Caddy 被停用，换成 Caddy 容器。请避开访问高峰。
5. 升级期间命令行和控制台会暂时连不上。

### 回滚

升级后发现问题，可以回到升级前的版本（程序和数据库一起回退）。先把升级脚本下载到服务器上，再运行。

正式版，中国大陆：

```bash
curl -fsSL https://gitee.com/VIP13390/AcornFox/raw/main/scripts/install/upgrade.sh -o upgrade.sh && sudo bash upgrade.sh --rollback
```

正式版，其他地区：

```bash
curl -fsSL https://github.com/OrbitMaker/AcornFox/releases/latest/download/upgrade.sh -o upgrade.sh && sudo bash upgrade.sh --rollback
```

**回滚不会再问确认，运行前请先看清副作用：**

- 回滚把控制面数据库（应用列表、版本记录、环境变量、域名等设置）恢复到升级前。**升级之后新建的应用、设的环境变量、绑的域名都会从列表里消失**；回到 v0.3.x 时，它不认识的应用容器也会被删掉。
- 这些应用的**数据卷不会删**，还在磁盘上（`docker volume ls` 能看到，名字以 `af-应用名-` 开头），可以重新部署后把数据找回来。
- 升级之前就有的应用、数据卷和数据库不受影响。
- 回滚到 v0.3.x 时，Caddy 容器会被删掉、系统里的 Caddy 重新启用，应用网址同样会断几秒。
- 服务器重启过也能回滚（最近一次备份的位置记在 `/var/lib/acornfox/backups/.last`）。

### 不支持用 `--version` 降级到 v0.3.x

v0.3.x 的程序读不了 v0.4.0 的数据库。升级脚本遇到 `--version v0.3.x` 会拒绝（`UPGRADE-DOWN-01`），加 `-y` 也一样，服务不停、什么都不改。想回到 v0.3.x，只能用上面的 `--rollback` 回到升级前的那份备份。

## 已知限制

- **Windows**：本版不提供程序，在服务器上直接用 `acornfox`（见“Windows 用户怎么用”）。在 Windows 的 Git Bash 里运行 `install-cli.sh` 只会说明本版没有 Windows 程序、改用 SSH，然后退出（退出码 2），不会下载或安装任何东西。
- **应用中心**：v0.5 开放，首批是 Hermes 智能体和 New API。现在控制台里的应用中心只是预告。
- **Mac 本机运行**：即将支持。本版 Mac 上只能装命令行，用来经 SSH 管理 Linux 服务器。早先用开发版在 Mac 上试装过本机服务的，开机自启还在，新版命令行装上后它会反复启动、停在 `SETUP-MAC-01`；运行一次 `acornfox uninstall` 清掉开机自启（默认保留数据，`--purge` 才删数据）。
- **arm64 Linux**：程序照常发布，安装脚本也允许，但还没有实测过。
- **Mac 命令行**：安装脚本做过核对，本版没有在 Mac 真机上实测安装。程序没有 Apple 开发者签名；用上面的命令安装不会被 Gatekeeper 拦，自己用浏览器下载程序时可能会被拦。
- **家用宽带安装 Docker 较慢**：不在云上的机器装 Docker 可能要 15～40 分钟；“安装 Docker...”这一步几分钟没有新输出是在下载，不是卡住。
- **域名证书迁移**：从 v0.3.x 升级时证书会复制到 Caddy 容器，用的是同一个证书账号；用真实域名“升级后证书继续用、不重新签发”这一点还没有实测。
- 控制台里的应用中心目前只是预告，还不能安装应用。

## 安装和运行时会连接哪些地方

AcornFox 不上报使用数据。下面是安装、升级和运行时会访问的地址。

### 安装、升级脚本（在服务器上）

| 做什么 | 访问哪里 | 什么时候 |
| --- | --- | --- |
| 判断在哪家云、哪个地域，取公网 IP | 阿里云、腾讯云、火山引擎、华为云的实例元数据接口 | 每次安装、升级；只在云主机内部能访问，不在云上时很快超时跳过 |
| 判断是否在中国大陆 | `ip-api.com` | 认不出是哪家云时 |
| 查最新版本号、下载程序和脚本 | 中国大陆：先 Gitee 发行版（`gitee.com`），失败再 GitHub；其他地区：GitHub（`github.com`） | 安装、升级 |
| GitHub 下载加速 | `ghfast.top`、`gh-proxy.com`，或你用 `ACORNFOX_GITHUB_PROXY` 指定的地址 | 只在中国大陆、直连 GitHub 失败或太慢时 |
| 系统软件源（APT） | 云厂商内网源；中国大陆还有 `mirrors.huaweicloud.com` | 系统原来的源指向 Ubuntu、Debian 官方地址时才换；其他源原样保留 |
| Docker 安装包 | 云厂商内网源；中国大陆依次是华为、腾讯、阿里、南京大学、清华镜像站；其他地区 `download.docker.com` | 安装 Docker 时（`--skip-docker` 跳过） |
| Caddy 安装包 | 中国大陆先从 Gitee 发行版取，再 GitHub 上的 Caddy 官方发行版；校验文件取自 Caddy 官方 | 安装时，本机还没有 Caddy 镜像的话 |

### 运行时（服务器上的 AcornFox 服务）

| 做什么 | 访问哪里 | 什么时候 |
| --- | --- | --- |
| 拉取应用和数据库镜像 | Docker Hub；镜像加速 `docker.m.daocloud.io`、`docker.1panel.live`，腾讯云服务器还有腾讯云内网加速；ghcr.io 的镜像在中国大陆走 `ghcr.nju.edu.cn` | 部署、加数据库时。中国大陆先用加速、Docker Hub 最后；其他地区先 Docker Hub，卡住或失败才用加速 |
| 拉取代码 | 你在 `deploy --git` 里给的仓库地址 | 用 Git 仓库部署时 |
| 构建 | 你的 Dockerfile 里写的软件包源（npm、pip 等） | 构建镜像时 |
| 申请 HTTPS 证书 | Let's Encrypt | 绑定域名、开公网控制台时 |
| 取公网 IP | 云厂商元数据接口；取不到再问 `4.ipw.cn`、`ipv4.icanhazip.com`（IPv6 是 `6.ipw.cn`、`ipv6.icanhazip.com`） | 只在开公网控制台时 |

### 命令行（在你自己的电脑上）

- 安装命令行：中国大陆先 Gitee 发行版，再 GitHub 和上面的下载加速；判断是否在中国大陆时会访问云厂商元数据接口和 `ip-api.com`。
- 管理服务器：只通过 SSH 连你登记的服务器。

### 下载网关 `dl.acornfox.com`

AcornFox 下载网关只在 Mac、Windows **本机准备运行环境**时使用（给大文件签发临时下载地址）。本版这个功能还没开放，Linux 服务端和命令行都不会联系它。

## 发行文件

| 文件 | 用途 |
