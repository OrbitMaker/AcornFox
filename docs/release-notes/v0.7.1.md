# AcornFox v0.7.1 发行说明

## 这一版是什么

修好中国大陆机器安装时选下载源的问题，加两样小功能：平台有新版本时提醒你，能看到这台机器上不是从 AcornFox 装的容器。

- **安装时当场测速选源**：一行命令安装、升级时，没写 `--china` 或 `--global` 的，会同时试 Gitee 和 GitHub，哪边快用哪边，屏幕上会显示一行“测速：Gitee x MB/s、GitHub y MB/s，先用 …”。原来在国内用 Gitee 那条命令，也可能因为能连上 GitHub 而去 GitHub 下载核心程序，很慢；现在 Linux、Windows、Mac 三端用同一种判断，并一路传给后面的安装步骤。下载中途卡住会自动换另一个源。
- **平台有新版本提醒**：AcornFox 每 6 小时查一次有没有新的正式版（国内先查 Gitee）。有新版本时，“设置 › 这台机器”的升级一行会写出来，可以复制升级命令，或复制一段话交给 AI 工作台帮你升级；铃铛里提醒一次。命令行用 `acornfox update` 看、`acornfox update check` 现在查一次；`acornfox doctor` 也会提醒。不做一键升级，升级仍是在服务器上运行一条命令。
- **这台机器上的其他容器**：“我的应用”最下面多一组“这台机器上的其他容器”，默认收起，列出你自己用 docker 或别的工具装的容器（名字、在不在跑、端口、内存），只显示、不管理；首页的资源图把它们算成“其他容器”。命令行用 `acornfox other-containers`。Windows、Mac 上只能看到 WSL 或虚拟机里面的容器。
- **其他**：Mac 第一次装苹果 container 和内核时，Skill 写清楚了正常是什么样子、怎么确认、已经装了别的版本时先问用户。

升级（Linux 服务器）：

```bash
# 中国大陆
curl -fsSL https://gitee.com/VIP13390/AcornFox/raw/main/get.sh | sudo bash -s -- upgrade
# 其他地区
curl -fsSL https://github.com/OrbitMaker/AcornFox/releases/latest/download/get.sh | sudo bash -s -- upgrade
```

Windows、Mac 的升级命令见 README 对应的一节。

## 升级前请看（已知影响）

- 测速判断 GitHub 更快时，会按“非中国大陆”安装（不用国内镜像源）。少数机器能快速连 GitHub、却连不上 Docker Hub 的，请在命令后加 `-s -- --china`（Windows 加 `-China`）。
- 查新版本会定期访问 Gitee 或 GitHub 的发行版接口；不想要可以设环境变量 `ACORNFOX_UPDATE_CHECK=off`。
- 升级时 AcornFox 服务停几秒，这几秒控制台打不开，应用不受影响。从 v0.6.x 升上来的，先看 [v0.7.0 的发行说明](v0.7.0.md) 里的“升级前请看”。

## 支持哪些平台、怎么安装

和 v0.7.0 一样：Linux 服务器（amd64、arm64）、Windows 10/11（x64）、Mac（苹果芯片、macOS 26 起），见 README。

指定装这一版：在安装命令后面加 `-s -- --version v0.7.1`。

## 这一版测了什么、没有测到什么

测了：

- Linux：全新安装、从旧版本升级两条回归路径；真网络下测速选源（Gitee、GitHub 都通、只通一边、都不通、差不多快）。
- Windows 11：从干净存档用一行命令安装，测速结果传进 WSL 里的安装，控制台能打开，卸载干净。
- 新版本提醒：真查 Gitee、GitHub；用假的新版本走了页面、接口、命令行。
- 其他容器：在 Linux 测试机上真起一个自己装的容器，能列出来，平台自己的容器不会被列进去。

没有测到：

- Mac：只做了编译和单元测试，没在真 Mac 上重装。
- 新版本提醒在 Windows、Mac 上显示的升级命令只有单元测试。
