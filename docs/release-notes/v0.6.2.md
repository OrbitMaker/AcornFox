# AcornFox v0.6.2 发行说明

## 这一版是什么

这一版围绕“谁能打开”做了四件事：

- **平台域名**：给整台服务器配一个域名，开放到公网的应用自动得到 `应用名.你的域名`，带 HTTPS，不用记端口。个别应用仍然可以另绑自己的域名，两个都有时用自己的。
  - 页面：设置 › 访问 › 域名。命令行：`acornfox domain base`（看现状和检查）、`acornfox domain base set 域名`、`acornfox domain base clear`。
  - 怎么配：到你买域名的地方加一条记录（名字 `*.子域`、类型 A、指向这台服务器的公网地址），再把域名填上。页面和命令行都会告诉你该加哪一条。
  - 有三项检查：域名指过来没有、外面能不能连到 80 和 443、证书。哪项不过会说明怎么办，并带故障编号（`PDOMAIN-01` 起）。
- **公网控制台可以在页面上开和关**：设置 › 访问 › 在外面打开控制台。默认仍然不开；开之前会先确认、要再输一次现在的控制台密码，开启后给一个新密码，只显示一次。配了平台域名时，地址默认是 `console.你的域名`。原来在服务器上用命令开关的办法照旧。
- **“设置 › 访问”这一页重新整理**：三行——域名、局域网里打开控制台、在外面打开控制台，每行一句现状，点开才看到细节。
- **新装的局域网服务器上，应用默认局域网里就能打开**：从应用中心装的应用不用再先开隧道或手动改访问方式。云主机上仍然默认只本机。要不要开放到公网，仍由你在每个应用上选。

另外：

- `acornfox open --detach`：把到服务器的安全通道放到后台，打开浏览器后马上返回（给 AI 工作台用，不会卡住）；`acornfox open --stop` 关掉它。
- 安装脚本新参数 `--default-exposure lan|local`：装的时候指定新应用默认谁能打开。
- `acornfox install 应用 --plan` 里每个应用多一项 `exposure`，写装好后是哪种对外方式。
- Skill：装到服务器以后固定一步“打开控制台”；加了“配平台域名”一节。

升级：

```bash
# 中国大陆
curl -fsSL https://gitee.com/VIP13390/AcornFox/raw/main/get.sh | sudo bash -s -- upgrade
# 其他地区
curl -fsSL https://github.com/OrbitMaker/AcornFox/releases/latest/download/get.sh | sudo bash -s -- upgrade
```

## 升级前请看（已知影响）

- **升级上来的服务器，应用默认谁能打开不变。** “默认局域网”只对这一版起全新安装的局域网服务器生效；老机器想要同样的效果，在应用的“设置 › 谁能打开”里改，或装的时候加 `--expose lan`。
- **平台域名只在有公网地址的服务器上能用。** 证书要从公网验证，所以局域网里的服务器（家里、公司内网）和 Mac、Windows 电脑这一版用不了，页面和命令行会直接说明（`PDOMAIN-02`）。
- **平台给的子域名只给访问方式是“公网”的应用。** 配了平台域名不会把应用自动开放到公网；应用改回局域网或只本机后，子域名随即失效。
- **证书是每个子域名单独申请的**，第一次打开前要等几十秒到几分钟。同一个主域名一周最多申请 50 张（证书签发方的限制），应用很多时要留意。
- **中国大陆的服务器，域名要先完成备案**，否则 80、443 会被拦。
- **三项检查里“外面能不能连上”是从服务器连自己的公网地址查的。** 有的云不允许服务器这样连自己，可能把通的报成不通（`PDOMAIN-03`）；这时以从别的地方实际打开为准。页面上开启公网控制台时的域名验证是同一种做法，遇到这种情况改用服务器上的命令 `acornfox public-console enable 域名`。
- 从公网控制台自己登录进来时，页面上只能关闭公网控制台，不能开或换地址。
- 升级时 AcornFox 服务停几秒，这几秒控制台打不开，应用不受影响。从 v0.6.0、v0.6.1 升上来不会再换入口容器。
- 还在用 v0.5.1 及更早版本的，升级前先看 [v0.6.0 的发行说明](v0.6.0.md) 里的“升级前请看”。

## 支持哪些平台、怎么安装

和 v0.6.0 一样，见 [v0.6.0 的发行说明](v0.6.0.md)。指定装这一版：在安装命令后面加 `-s -- --version v0.6.2`。

## 这一版测了什么、没有测到什么

测了：

- 用真域名在一台有公网地址的云主机（阿里云）上走过：配平台域名、公网应用用 `https://应用名.域名` 打开、证书由 Let’s Encrypt 签发并通过校验、应用自己的域名优先、改回局域网和清掉域名后失效、公网控制台的开和关。**新入口代理下用真域名申请证书，这次实测可用**（v0.6.0、v0.6.1 的发行说明里写过“还没有实测”）。
- 全新安装和从旧版本升级两条回归路径；全新安装的局域网服务器上应用默认局域网。

没有测到：

- 用较弱的模型只凭 Skill 走“配平台域名”“装完打开控制台”。
- 在有公网地址的服务器上用浏览器点页面（那几个接口是用和页面相同的方式调通的）；“再输一次密码”那条保护只有自动测试。
- 换一个平台域名；应用名不能当子域名的情况；阿里云以外的云和境外服务器。
- Mac、Windows 上的浏览器；手机宽度下的排版。
