# AcornFox v0.5.1 发行说明

## 这一版是什么

这一版主要修好“删掉应用、再接上旧数据重装会丢设置”：改过的配置文件、用 `--set platform.…` 改过的设置、大模型来源都按原来的接上。在 v0.5.0 上要换应用版本（删除后接上旧数据重装）的，请先升级到这一版再做。

另外：

- **局域网控制台**：局域网里的服务器全新安装时默认打开，第一次打开时在浏览器里自己设密码，可以记住设备 90 天。
- **故障编号都能查**：新命令 `acornfox faults 编号` 给出任何故障编号的完整说明和处理办法；`acornfox doctor` 多查“下载网关”“应用目录”两项（下载网关一项要用 `sudo acornfox doctor` 才查）。
- **应用中心**：`acornfox install status 任务编号 --wait` 等到装完再返回；要先升级 AcornFox 才能装的应用提前标出来；`acornfox apps vars` 看一个应用是用什么设置装的；镜像包按 CPU 架构取。
- **控制台**：应用概览加了内存、CPU 小图，主色可以选。
- **修复**：控制台“设置 → 访问”看不到局域网控制台；不加 `--json` 时出错输出补上故障编号；向下载网关要下载地址时多等一会儿，在国内装 Hermes 不容易再退回很慢的公共源。见下面“其他修复”。

## 支持哪些平台

| 平台 | 本版提供的程序 | 说明 |
| --- | --- | --- |
| Linux x86_64（amd64） | 服务端 + 命令行 | 正式支持。Ubuntu 22.04、24.04，Debian 12、13；推荐 Ubuntu 24.04 或 Debian 13 |
| Linux arm64 | 服务端 + 命令行 | 安装脚本允许安装，但**还没有实测** |
| macOS（Apple 芯片、Intel） | 只有命令行 | 在 Mac 上装命令行，经 SSH 管理 Linux 服务器。本版不提供在 Mac 本机运行 AcornFox 服务端，在 Mac 上运行不带应用名的 `acornfox install` 或 `acornfox doctor` 只会提示还不能用（`SETUP-MAC-01`） |
| Windows | 不提供 | 用 SSH 登录服务器，在服务器上运行 `acornfox`，做法见 [使用手册](../user-guide.md#windows-电脑经-ssh-在服务器上操作) |

建议配置：2 核 2 GB 以上；需要 root 或 sudo。要装 Hermes 智能体，内存建议再留出 2 GB，磁盘至少留 6 GB。

## 安装

在 Linux 服务器上运行（按服务器所在网络选一条）。

中国大陆：

```bash
curl -fsSL https://gitee.com/VIP13390/AcornFox/raw/main/scripts/install/install.sh | sudo bash
```

其他地区：

```bash
curl -fsSL https://github.com/OrbitMaker/AcornFox/releases/latest/download/install.sh | sudo bash
```

用 AI 工作台安装，把下面这句话发给它：

```text
请安装 AcornFox Skill：下载 https://acornfox.com/skill/SKILL.md ，保存为你 skills 目录下的 acornfox/SKILL.md（Claude Code 是 ~/.claude/skills，Codex 是 ~/.codex/skills），然后按这个 Skill 把当前项目部署到我的服务器。
```

**注意：服务器在局域网里（私网地址、不是云主机）时，全新安装会默认打开局域网控制台（端口 18802）**，装完屏幕上给出地址，见下面“局域网控制台”。不想打开，安装时加 `--no-lan-console`（管道安装写成 `| sudo bash -s -- --no-lan-console`）。

## 新功能和改进

### 删了再接上旧数据重装，不丢设置

删除应用默认保留数据。用同一个名字再装时加 `--reuse-data`（页面上是“接上旧数据重装”），这一版起，这次没写的设置都按以前的来：

| 设置 | 怎么处理 |
| --- | --- |
| 账号密码、平台生成的密钥 | 和以前一样（v0.5.0 就是这样） |
| 以前用 `--set platform.名字=值` 改过的平台变量（例如时区） | 恢复成以前改的值；这次又写了 `--set` 的，以这次为准 |
| 大模型来源 | 沿用原来的：自己的 Key 照旧；本机 New API 还在运行就接着用，连原来那把令牌也接着用；原来那个 New API 停着，会停下让你先启动它（`CAT-INST-10`，`acornfox start new-api` 后再装）；本机没有它了，会停下让你重新选（`CAT-INST-02`，错误里说出原来是哪个）。这次写了 `--llm` 的以这次为准（还是选原来那个本机 New API 时，原来那把令牌照样接着用） |
| 数据里已有的配置文件（例如 Hermes 的 `config.yaml`） | 不重写，你和应用自己改过的内容都留着。只有平台要往里填的内容变了（这次换了大模型、原来那把令牌已经没有了、新版本的应用改了配置模板）才按这次的设置重写；重写前把旧文件另存为 `config.yaml.bak-时间`，要的内容可以从里面抄回来。上一次接旧数据没装好、配置文件已经被那次改写过的，这次也按这次的设置重写（旧文件同样另存） |
| 对外方式 | 回到默认的只本机；以前开放过局域网的，装好后再开一次 |

- 沿用了什么，安装进度的“建应用”“写配置”两步里写着；命令行装好后列出“沿用的设置”。`--json` 的任务里，每个应用多了 `carried`（沿用了什么，一条一句）、`taken_gateway_token`（接着用的旧令牌，只有编号）、`kept_files`（没重写的配置文件）、`file_backups`（重写了的文件和旧文件另存的名字）。
- **删除时保留数据，令牌不再吊销**：用了本机 New API 的应用（例如 Hermes）只删应用、保留数据时，给它的令牌跟着数据留下（它的配置文件里存着这把令牌），接上旧数据重装时接着用。连数据一起删（`--volumes`）时照旧吊销。接上旧数据时改用了别的大模型，或者同名全新安装（旧数据已经删掉）时，留下的旧令牌在装好后吊销；吊销前先核对 New API 里同一个编号的令牌还是原来那把，不会误删别的令牌。那时 New API 停着或连不上、没吊销成的，安装进度和命令行结果里会写“没能吊销以前在 … 里给 … 的令牌”，并说出名字和结尾 4 位，请在 New API 运行时到“令牌”页手动删掉它。
- 你在 New API 里停用了的旧令牌，接上旧数据时照样接着用，不会新发一把把你的停用顶掉；进度里会写明它现在调不了模型，要用就到 New API 的“令牌”页启用它。
- 换应用的版本仍然是“删掉应用（保留数据）→ 用原来的命令加 `--reuse-data` 装回来”，现在不用再把以前的 `--set`、`--llm` 写一遍。
- 已经发布的两个应用（New API、Hermes）的目录内容没有改。

### 局域网控制台

- **局域网里的服务器全新安装时默认打开**（端口 18802），装完屏幕上给出地址。判断依据是服务器的地址是私网地址、而且不是云主机；云主机和公网服务器开不了（`LAN-CONSOLE-01`），照旧用 `acornfox open`（经 SSH 隧道）。安装时加 `--no-lan-console` 就不开；18802 被别的程序占着时安装照常完成，只是这次不开。升级、保留数据卸载后再装都不会自动打开（`uninstall.sh --purge` 连数据删掉后再装算全新安装，会打开）。
- **第一次打开时在浏览器里自己设密码**（至少 8 位），局域网里谁先打开谁设；设好以后别的电脑只能登录。`acornfox lan-console enable` 不再生成密码。
- 登录时可以勾“记住这台设备 90 天”（最多记 20 台，再多就挤掉最久没用的那台）。设置页里能看到密码是什么时间、从哪个地址设的，能移除记住的设备。
- 只认局域网来源：10.x、172.16.x～172.31.x、192.168.x、100.64.x～100.127.x、169.254.x、IPv6 的局域网地址和本机，别的来源一律拒绝（`LAN-CONSOLE-02`）。开着但还没设密码时 `acornfox doctor` 会提醒（`LAN-CONSOLE-03`）。
- 服务器上的命令：`acornfox lan-console status`、`enable`、`disable`（关闭，密码、登录和记住的设备一起清掉）、`reset-password`（清掉密码，登录和记住的设备一起作废，之后在浏览器里重设）、`devices`、`forget 编号|--all`，都有 `--json`。
- 登录页换成新控制台的样子，局域网入口和公网域名入口共用。
- v0.5.0 打开的局域网控制台和它生成的密码，升级后照常能用。**以前在云主机上打开过局域网控制台、从公网地址访问的，升级后会被拒绝，请改用 `acornfox open`。**

### 故障编号都能查：`acornfox faults`

- `acornfox faults 编号` 给出一个故障编号的完整说明：是什么、会看到什么、可能的原因和怎么判断、按什么顺序查、怎么处理、什么时候要先问你、怎么确认好了。安装和升级脚本、`acornfox doctor`、应用中心、部署诊断、控制台“运行环境”页里出现的编号都收在里面。大写的编号（例如 `CAT-INST-24`）不分大小写，小写的诊断码（例如 `build_failed`）照原样写。
- 处理办法分三级：0 级只读；1 级可以直接做（不删数据、不花钱、不对外开放、做了能撤回）；2 级要你先同意。
- `acornfox faults` 列出全部编号，`--group 组名` 只列一组，`--json` 给 AI 工作台读。全文也在仓库的 [故障目录](../faults.md)。
- 只读，不连服务器：目录编在程序里，和这个 `acornfox` 的版本一致，Mac 上的命令行也能查。查不到的编号（例如比这个程序新的）按兜底条目 `ANY-00` 处理：先照出错输出里的 message 和 hint 做。
- 后台服务也提供只读接口 `GET /v1/faults`、`GET /v1/faults/{编号}`。

### 自检多查两项

- `acornfox doctor` 和控制台“运行环境”页多了两项，都只给警告，不影响别的：
  - **下载网关**（`SETUP-GW-01`）：连不连得上、应答对不对、和本机时间差多少。网关不通时，公共目录的应用照常能装，镜像改从公共源拉，会慢一些。这一项要用 `sudo acornfox doctor` 才查：普通用户读不到数据目录里的网关设置，这一项写“读不到……没查”（显示为通过，但其实没查），也不联系网关。控制台“运行环境”页由后台服务查，不受影响。
  - **应用目录**（`SETUP-SYNC-01`）：上次什么时候同步、成没成、从哪里取的、在用哪一份目录；超过两天没同步会提醒。这一项只读上次同步的结果，不联网。
- 时钟检查和下载网关检查共用一个请求，网关不回应时整次自检最多多等约 5 秒。

### 应用中心

- **查安装进度可以等到装完**：`acornfox install status 任务编号 --wait` 等到装好或失败才返回（每 2 秒查一次，默认最多 90 秒，`--timeout 秒` 可改，最多 600；没装完就照实返回，再运行一次接着等）。输出里写着装到了哪一步、每一步和整次各用了多久、算不算比平常慢；某一步比平常慢很多时提示 `CAT-INST-30`（还没失败），并给出看原因的命令。`--json` 里有 `done`（有结果了没有）、`stuck`、`say`（可以原样告诉用户的话）、`next_command`（下一步运行什么）、`must_tell`（装好后必须告诉你的话，例如没能吊销的旧令牌），AI 照着做就行，不用自己判断。连 v0.5.0 的服务器也能用，时长由命令行自己算。
- 安装进度里，从公共源拉镜像这一步写明是从公共源拉、看不到进度；还没开始的步骤写“还没开始”。
- **要先升级才能装的应用提前标出来**：目录里的应用或配方要求比这台更新的 AcornFox 时，列表和详情里标“要先升级到 x.y.z”并给出升级命令（`--json` 里是 `needs_platform`），安装按钮灰掉、不下载镜像。安装时也先比版本（`CAT-INST-08`，错误里带 `needs_platform`）。
- **应用包的清单安装前先严格检查**：里面有这个版本不认识的写法时，什么都不建就拒绝（`CAT-INST-29`），并说清楚是要先升级 AcornFox，还是这份目录有问题（升级也没用，过一会儿再试）。
- 配方也能要求最低版本；v0.5.0 看不到它装不了的配方。
- **查看一个应用是用什么设置装的**：`acornfox apps vars 应用名`（`--json` 也行）。每个变量一行：值、是谁给的（你填的、平台生成的、平台按这台机器算的、你用 `--set platform.…` 改的、接上旧数据时恢复的……）、清单写的能不能改。密码和 Key 默认只显示后 4 位，`--reveal` 才显示全。只能看，还不能改。
- 安装时把当时的应用清单存下来；v0.5.0 装的应用，升级后在后台按本机能找到的应用包补存。
- **按 CPU 架构取镜像包**：目录里的镜像包可以按 CPU 架构分开写，安装时只下载这台机器架构的那个。目录里没有这台机器架构的包时（例如现在的 Hermes 在 arm64 服务器上），不再导入别的架构的包，改从公共镜像源拉，进度里写明原因；本机已有的同一个镜像如果是别的架构的，也不直接用。磁盘空间只按要下载的那个包算。用了按架构写法的应用要 v0.5.1 起才能装：v0.5.0 的列表里照常显示它，点安装时报 `CAT-INST-08`（要先升级 AcornFox），什么都不建。
- **要用的本机 New API 停着时直接说清楚**：选了本机 New API（或配方、接旧数据时原来用的就是它）而它被停掉了，提交时就拒绝（`CAT-INST-10`），错误里写“装着但停着”，建议先 `acornfox start` 它；不再等到安装途中才失败、还建议你再装一个 New API。
- 给目录作者用的检查：`acornfox catalog lint` 自动算出清单最低要哪个平台版本、写低了报错（`CAT-LINT-17`），检查按架构写的镜像包（`CAT-LINT-20`、`CAT-LINT-21`）；`acornfox catalog vars` 列出一个应用装的时候哪些变量要用户动手（`CAT-LINT-18`）；`acornfox catalog gaps` 核对“平台还缺的变量”登记（`CAT-LINT-19`）。

### 控制台

- 应用概览最上面加了内存、CPU 两张小图（近 1 小时或 24 小时）。每 30 秒记一次，只存在内存里，后台服务重启（包括升级）后从头记；应用停着的时候不记。命令行：`acornfox stats 应用名 --history 1h`（或 `24h`）。
- 设置 → 通用：主色四选一（中性、蓝、绿、橙），默认中性，记在当前浏览器里。
- 应用中心：要先升级才能装的应用标出来并给升级命令；应用详情读不出来时显示列表里的基本信息，并说明要先升级。

### AcornFox Skill

- 给 AI 工作台用的 Skill 跟着更新：加了“遇到故障编号怎么办”（先 `acornfox faults 编号`，分清能直接做的和要先问你的）、“换应用版本、删了再接上旧数据重装”、“要先升级 AcornFox 才能装的应用”、“查一个应用是用什么设置装的”；装应用时用 `install status --wait` 等到装完再下结论；局域网控制台按这一版的做法改了。
- 以前装过 Skill 的，升级命令行后运行一次 `acornfox skill install` 换成新版（或者重新下载 `https://acornfox.com/skill/SKILL.md`）。

### 其他修复

- **控制台“设置 → 访问”看不到局域网控制台**（v0.5.0 就有：这一页不显示局域网控制台那一行）：在浏览器里的控制台读不到局域网控制台的状态，经 SSH 隧道打开的、局域网控制台（18802）本身和公网控制台（自己的域名）都是这样，所以这一页看不到局域网控制台开没开。现在能看了；v0.5.1 起还能在这里看到密码是什么时间从哪设的、移除记住的设备。命令行 `acornfox lan-console status` 一直能用。
- **不加 `--json` 时出错输出也写出故障编号**：例如 `故障编号：CAT-INST-24（运行 acornfox faults CAT-INST-24 查处理办法）`，把输出转给 AI 时编号不会丢；不是故障的通用错误码写成 `错误码：…`。以前只有加 `--json` 才看得到编号。
- **向下载网关要下载地址时多等一会儿**：等网关应答的时间从 10 秒放宽到 30 秒。网关偶尔要好几秒才应答，以前超过 10 秒就退回公共源，在国内装 Hermes 可能因此 10 分钟拉不完镜像而失败（`CAT-INST-12`）。网关一直不应答时，退回公共源前要多等约 20 秒（连不上的会马上退回）；下载文件本身不受这个时限影响。
- **关掉下载网关后，不加 sudo 的 `doctor` 还会联系网关**（v0.5.0 就有）：普通用户读不到数据目录里的 `network.json`，看不出网关已经关掉，照旧发 HEAD。现在读不到这个设置时不联系网关，“下载网关”一项写明没查、要查用 `sudo acornfox doctor`。
- **拉镜像超时说清楚了**：从公共源拉镜像超过 10 分钟时，部署报 `pull_timeout`（建议配镜像加速），从应用中心装应用报 `CAT-INST-12`，消息里写明是拉取镜像超时；不再只报笼统的 `runner: unavailable`。

## 从 v0.5.0 升级

在服务器上运行（按服务器所在网络选一条）。

中国大陆：

```bash
curl -fsSL https://gitee.com/VIP13390/AcornFox/raw/main/scripts/install/upgrade.sh | sudo bash
```

其他地区：

```bash
curl -fsSL https://github.com/OrbitMaker/AcornFox/releases/latest/download/upgrade.sh | sudo bash
```

- 管道运行就视为同意升级；已经是最新版本时直接退出，不停服务。只有要重装同一版本时才加 `-y`。
- 升级前把程序和数据库备份到 `/var/lib/acornfox/backups/`（保留最近 5 份），再做数据库迁移（新增一张表，存每个应用安装时的清单）；应用容器一直运行，升级期间命令行和控制台会暂时连不上。
- AcornFox 只能升级，不能回到旧版本；升级没成功时会自动恢复到升级前。
- 升级不会打开局域网控制台；原来开着的照常能用（见上面“局域网控制台”最后一条）。
- 先升级服务器，再升级自己电脑上的命令行（重新运行一次安装命令行的命令）。新命令里，`apps vars`、`stats --history` 要服务器也是 v0.5.1；`faults` 不连服务器；`install status --wait` 连 v0.5.0 的服务器也能用。局域网控制台的命令请用 v0.5.1 的命令行：`lan-console reset-password`、`devices`、`forget` 要服务器也是 v0.5.1；v0.5.0 的命令行对 v0.5.1 的服务器运行 `lan-console enable` 会说“密码没变”，其实这一版已经不生成密码，第一次打开时在浏览器里设。
- **在 v0.5.0 上删除、保留了数据的应用**，升级后接上旧数据重装时：账号密码照旧；v0.5.0 删除时已经吊销了 Hermes 的令牌，所以会新发一把，Hermes 的 `config.yaml` 按新令牌重写，旧文件另存为 `config.yaml.bak-时间`。
- **在 v0.5.0 上装的应用**（不管是在 v0.5.0 还是升级后删除的），接上旧数据重装时：v0.5.0 不记哪些平台变量是你改过的，以前用 `--set platform.…` 改过的（例如时区）要这次再写一遍，不写就用这台机器现在的值（安装进度里会提醒）。在 v0.5.1 上装的应用会记下来，以后不用再写。

## 已知限制

- **应用升级**：还没有把已装的应用升级到目录里新版本的功能。换版本用“删除（保留数据）→ 原来的命令加 `--reuse-data` 重装”，设置会沿用；新版本能不能读旧数据由应用自己决定，重要的数据请先自己备份。
- **装好后改设置**：还不能改，`acornfox apps vars` 只能看。
- **保留了数据、后来不想要了**：还没有删除这类旧数据卷的命令，要用 `docker volume rm` 删（卷名在 `CAT-INST-24` 的错误里）。这样删掉的，Hermes 留在 New API 里的令牌不会自动吊销，请在 New API 的“令牌”页删掉 `acornfox-hermes-agent`（之后用同名全新安装也会自动吊销）。
- **页面上接旧数据重装**：安装表单里选的大模型来源会一起提交，算“这次写了”；和原来不一样时，配置文件会按新的重写（旧文件另存）。想完全按原来的，用命令行不写 `--llm`。
- **New API 的登录限流**：New API 限制同一来源 20 分钟里最多登录、取令牌 20 次。短时间里反复删、装用本机 New API 的应用，可能报 `CAT-INST-11`（错误里有 HTTP 429），等 20 分钟再装，不要反复重试。
- **安装“比平常慢”“卡住”的提示**：各步骤的正常时长是在 2 核 4 GB 的测试机上实测的；“慢”“卡住”两种情况还没在真机上造出来过，只有自动测试。这只是提醒，不会取消安装。
- **局域网控制台**：页面上还不能改密码，要在服务器上 `acornfox lan-console reset-password` 后在浏览器里重设；局域网里是明文 HTTP。“设置 → 访问”的记住设备列表里还没标出哪台是你正在用的这台，移除这台会马上退出、要重新输密码，移除前不另外提示。
- **镜像还没拉完时删附加服务**：刚 `acornfox add redis`（或 postgres、mysql）、镜像还没拉完就 `acornfox remove redis`，命令先返回“已删除”，容器要等镜像拉完、建出来后再过几秒才真删掉，这期间 `docker ps` 还能看到它。最终状态是对的：没有这个容器，数据卷照常保留。
- **私有目录**：这一版不开放。
- **平台 Key**：这一版不能用（`CAT-INST-09`），大模型请用本机 New API 或自己的 Key。
- **Hermes 智能体**：安装约 3～4 分钟，主要花在下载和导入镜像上。上游程序启动时会访问 `nousresearch.github.io`（取能力目录），国内网络打不开，不影响对话。要求大模型的上下文不少于 64K。
- **Hermes 用的令牌不限额**：经本机 New API 时发给 Hermes 的令牌不限额、不过期，请在 New API 里自己设上限。
- **关掉下载网关后**：Hermes 的镜像改从公共镜像源拉，国内会慢很多，有时拉不下来。
- **资源历史**：整机和应用的资源历史都只存在内存里，最多 24 小时，后台服务重启后重新记；首页看板的网络流量、7 天历史等还没有。
- **arm64 Linux**：程序照常发布，安装脚本也允许，但还没在真的 arm64 机器上实测过；应用中心的两个应用也没在 arm64 上装过，按架构取镜像包只在 x86_64 机器上模拟测过。
- **Windows**：本版不提供程序，在服务器上直接用 `acornfox`。
- **Mac 本机运行**：本版不提供，Mac 上只能装命令行。
- **Mac 命令行**：程序没有 Apple 开发者签名；用安装命令安装不会被 Gatekeeper 拦，自己用浏览器下载程序时可能会被拦。

## 联网和隐私

AcornFox 没有使用统计，也没有崩溃上报。这一版没有新增要联系的 AcornFox 服务器，也没有新增联系的时机，和 v0.5.0 一样：

- **下载网关 `dl.acornfox.com`**：从应用中心装 Hermes 时用。第一次用时登记一个随机生成的机器编号和公钥，以及程序版本、系统和 CPU 架构；之后每次要下载地址时带签名。不读硬件信息，不发应用列表、项目代码、日志和密码。网关能看到服务器的 IP。
- **应用目录**：每天从 `acornfox.com/catalog` 同步一次，打不开时读 Gitee 上的备用副本。这是普通的下载请求，不带机器编号。
- **自检**：用 sudo（或 root）运行 `acornfox doctor` 时（普通用户运行时读不到网关设置，不发；自己在终端里设了 `ACORNFOX_GATEWAY` 的，按它写的地址发，设为空值的不发）；控制台的首页和“运行环境”页开着时，约每分钟一次；打开“设置”页时一次。每次向下载网关发一个不带内容的 HEAD 请求（最多等 5 秒，不带安装编号和签名）。v0.5.0 只读应答里的时间（查时钟）；这一版还看状态码，判断网关连不连得上。v0.5.0 的说明只写了 `doctor` 和“运行环境”页，首页和“设置”页其实也一样会发，这里补上。

接上旧数据重装时核对旧令牌，只访问本机的 New API。`acornfox faults` 不联网；局域网控制台只在你的局域网里提供页面，不联系外面。

下载网关可以关掉：`/var/lib/acornfox/network.json` 写 `{"gateway": "off"}`，`chown` 给后台服务的账号 `acornfox`，再重启服务（命令见使用手册）。关掉后，后台服务（包括控制台各页的自检）和 `sudo acornfox doctor` 都不再发这个请求；不加 sudo 的 `doctor` 读不到这个文件时也不联系网关（终端里设了 `ACORNFOX_GATEWAY` 的按它）。也可以只给后台服务设环境变量 `ACORNFOX_GATEWAY` 为空值，但它只对后台服务生效，终端里运行的 `doctor` 仍会发，所以推荐用 `network.json`。目录来源可以用 `ACORNFOX_CATALOG_SOURCES` 换成自己的副本。具体发了哪些字段、怎么关、关了会怎样，以及安装和运行时访问的全部地址，见 [使用手册的“隐私和联网说明”](../user-guide.md#隐私和联网说明)。

安装脚本会自动校验。手动下载程序后，在同一目录里核对：

```bash
sha256sum -c SHA256SUMS --ignore-missing
```
