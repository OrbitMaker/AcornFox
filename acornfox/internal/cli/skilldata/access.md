# 打开控制台和应用、绑域名、平台域名

**什么时候读这一册**：AcornFox 装好、服务器登记好以后要让用户在浏览器里看到控制台（`install-linux.md` 第 7 步之后）；用户问“怎么打开控制台”“手机上用”“局域网”“公网”“隧道”“忘了控制台密码”“怎么打开这个应用”“页面上哪里看”；要给应用绑域名、给整台服务器配平台域名、开 https。

## 第 7 步之后：打开控制台（固定一步）

登记好以后**固定做这一步，不用问用户**：让用户在浏览器里看到 AcornFox 控制台，之后他可以在那里看这台服务器、装应用、改设置。这一步只读，不改服务器上的任何东西。用户说过不要打开，就跳过。

**① 先看局域网控制台开没开**（在服务器上执行；情况乙、丙前面加 `ssh 用户@地址`；情况甲且 `connect-server.md` 第 7 步是 `group=added` 时照那一步定下的写法包一层）：

```bash
acornfox lan-console status --json
```

| 看到 | 下一步 |
| --- | --- |
| `enabled: true`（局域网服务器第一次安装时默认就开着） | 做 ②甲 |
| `enabled: false`、报 `LAN-CONSOLE-01`，或者命令不认识 `lan-console` | 做 ②乙 |

**②甲 局域网服务器：直接给地址，不用隧道。** 情况乙（你在用户电脑上）时，先在用户电脑上用浏览器打开 `url`（Mac 执行 `open 地址`，Linux 执行 `xdg-open 地址`；打不开就算了，地址照样给）。然后照抄告诉用户（`<url>` 换成返回里的 `url`）：

- `password_set: false`：“控制台已经能在同一局域网里的电脑、手机上打开：<url>。现在还没有密码，第一次打开时要先设一个（至少 8 位）；局域网里谁先打开谁设，请现在就去设。”
- `password_set: true`：“控制台在同一局域网里的电脑、手机上用 <url> 打开，用设好的密码登录。”

到这里这一步就做完了，不用再开隧道。

**②乙 云主机、公网服务器：经 SSH 隧道打开。** 按 `install-linux.md` 第 1 步的情况分：

- **情况乙**（你在用户电脑上，第 7 步用 `--ssh` 登记了服务器）：在用户电脑上运行下面这一条。`--detach` 让隧道在后台开着、命令马上结束；**不要**运行不带 `--detach` 的 `acornfox open`，它会一直占着前台等人按 Ctrl+C，你会卡住。

```bash
acornfox --json open --detach
```

  | 看到 | 下一步 |
  | --- | --- |
  | `"ok":true`，`browser_opened` 是 `true` | 照抄告诉用户：“浏览器已经打开了 AcornFox 控制台（<url>）。连接在后台开着，不用开着终端；电脑重启或断网后要再打开就跟我说。” |
  | `"ok":true`，`browser_opened` 是 `false` | 把 `login_url` 告诉用户，请他在浏览器里打开（一次性，60 秒内有效；过期就再运行一次上面这条命令，给新的链接） |
  | 报不认识 `--detach`（用户电脑上的命令行比 v0.6.2 旧） | 请用户在**他自己电脑**的终端运行下面这一行，它会打开浏览器；用的时候终端保持不关，用完按 Ctrl+C。你不要自己运行它 |
  | `diagnosis.stage` 是 `connect` | 按 `connect-server.md` 的“连接出错”处理，处理好再运行一次 |

  旧命令行时交给用户的那一行：

```bash
acornfox open
```

- **情况甲、丙**（你在服务器上，或者在 Windows 上经 ssh 运行命令）：用户电脑上的隧道你建不了。发一条消息，请用户在**他自己电脑**的终端运行下面这一行并保持不关，开好了回复“好了”（`用户@地址` 换成他登录这台服务器用的）：

```bash
ssh -N -L 18800:127.0.0.1:18800 用户@地址
```

  用户回复后，你在服务器上执行 `acornfox open --no-browser`（情况丙：`ssh 用户@地址 'acornfox open --no-browser'`；都不加 `--json`），把输出的登录链接告诉用户在他电脑的浏览器里打开（一次性，60 秒内有效，过期就再执行一次）。用户电脑是 Linux、Mac 时，也可以按 `connect-server.md` 第 7 步情况乙在他电脑上装命令行、登记，以后用 `acornfox open`。

**不用问用户的**：`lan-console status`；`acornfox --json open --detach`（只在用户电脑上开一个本地端口和一条 SSH 连接，不改服务器）；在用户电脑上用浏览器打开地址。

**必须先问用户的**：

- 关掉后台隧道（`acornfox open --stop`，在用户电脑上运行）：用户说不用了才关。
- 局域网控制台没开、用户想在局域网里打开：先确认这台机器在他自己的局域网里，再照下面“局域网打开控制台”开（写操作）。
- 对公网开放控制台：照下面“公网访问控制台”，用户明确要了才做。

## 打开某个应用（只本机的应用）

云主机上（还有 v0.6.2 之前装的机器），从应用中心装的应用默认只本机能打开（`exposure: local`）：`apps[].url` 是 `http://127.0.0.1:端口`，只在服务器自己身上能用，用户在自己电脑上点不开。局域网里新装的服务器上默认是 `lan`，`apps[].url` 就是局域网地址，直接给用户，不用看这一节。**不要**让用户去安全组或防火墙放行端口（应用只听本机地址，放行了也打不开）。

**最低路径（照着做）：** 运行 `acornfox --json apps`，找到这个应用。`internal_only: true`（数据库、缓存这类，只在内部网络）：告诉用户“它只在内部网络，是给别的应用用的，没有网页，不用打开”，到此为止；`acornfox open`、`app set --expose`、绑域名对它都不适用（报 `OPEN-APP-03` 或 `internal_app`），不要去试。`local_only` 不是 `true`（`exposure` 是 `lan`、`public`，已经开放）：运行 `acornfox --json status 应用名`，把最外层的 `lan_url`（没有就用 `url`）告诉用户。`local_only: true`：照 `app-center.md` 第 7 步的 ③（怎么打开）和 ⑥（最后的问题）的样板写给用户，两条命令都给，规矩一样。`acornfox open 应用名` 像 `acornfox open` 打开 AcornFox 控制台一样开一条 SSH 隧道，要求用户电脑上装了 CLI 并按 `connect-server.md` 第 7 步（登记服务器）用 `--ssh` 登记了这台服务器。

`acornfox open 应用名` 出错带 `OPEN-APP-…` 编号时，照入口规则 `acornfox faults 编号` 查。几个固定的：应用还没有访问端口（`OPEN-APP-01`）：`acornfox --json status 应用名` 看部署状态，部署成功后再打开；这台服务器是用网址（局域网或公网控制台）登记的、开不了隧道（`OPEN-APP-02`）：按 `connect-server.md` 第 7 步用 `--ssh` 再登记一次，或者给 `tunnel_command` 那条，或者照 `app-center.md` 第 7 步 ⑥ 问用户，同意后改成局域网；应用只在内部网络（`OPEN-APP-03`，数据库、缓存这类）：告诉用户不用打开它，要看的是用它的那个应用；`diagnosis.stage` 是 `connect`：按 `connect-server.md` 的“连接出错”处理。

## 网页控制台

控制台只在服务器本机监听，不对外开放。

- 情况乙：你（AI 工作台）在用户电脑上执行 `acornfox --json open --detach`：它经 SSH 转发、打开浏览器，隧道留在后台，命令马上结束（v0.6.2 起；输出怎么看见“第 7 步之后：打开控制台”）。用完关掉用 `acornfox open --stop`（先问用户）。用户自己在终端里用时是 `acornfox open`，看完按 Ctrl+C 关闭；你不要运行不带 `--detach` 的 `acornfox open`，它会一直占着前台。
- 情况甲：请用户在**他自己电脑**的终端运行 `ssh -L 18800:127.0.0.1:18800 用户@地址` 并保持不关；然后你在服务器上执行 `acornfox open --no-browser`（不加 `--json`），把输出的登录链接告诉用户在自己电脑的浏览器里打开。链接一次性、60 秒内有效，过期就再执行一次。用户电脑是 Linux、Mac 时，更省事的做法是在他电脑上装 CLI，按情况乙第 7 步登记后用 `acornfox open`。
- 情况丙：同情况甲，请用户在 Windows 的终端（Git Bash 或 PowerShell）运行 `ssh -L 18800:127.0.0.1:18800 用户@地址` 并保持不关；你执行 `ssh 用户@地址 'acornfox open --no-browser'`，把输出的登录链接告诉用户在浏览器里打开。

打开某个应用的页面（不是 AcornFox 控制台）：情况乙在用户电脑上运行 `acornfox open 应用名`，同样经 SSH 隧道、按 Ctrl+C 关闭；只本机的应用也能这样打开，不用改对外方式、不用放行安全组。完整步骤见 `app-center.md` 的“从应用中心装应用”里的“装好后怎么打开”。

### 用户问“在页面上哪里看”（v0.6.3 起）

用户想自己在控制台页面上看时，照这张表告诉他位置；你自己要查，用右边的命令，两边是同一份数据。服务器是 v0.6.3 之前的版本时页面上没有这几处：照实说要升级到 v0.6.3 才有，先用右边的命令替他查。

| 用户想看的 | 页面上在哪 | 同一件事的命令 |
| --- | --- | --- |
| 这台机器上有哪些服务、谁提供、谁在用 | “设置 › 服务”：一条服务一行，点开看各项的值、“试一下”、能不能删 | `acornfox --json services list` |
| 平台替应用自动填了什么（时区、下载源这几项） | “设置 › 服务”最后一行“平台自动填的”，点开看 | `acornfox --json catalog platform-vars` |
| 某个应用连着谁的服务、谁在用它的服务 | 应用详情“概览”页签里的“连接”卡片 | `acornfox --json status 应用名` 的 `services`；`acornfox --json services list` 的 `used_by` |
| 某个应用是用什么设置装的 | 应用详情“设置”页签里的“安装设置”一行，点开看；其余的在“全部显示”里 | `acornfox --json apps vars 应用名` |
| 某个应用或解决方案的一句话、介绍 | 应用中心里点开它，页面上那一篇介绍 | `acornfox --json catalog show 应用编号` |

说给用户听时注意这几点（页面上是给不懂技术的人看的说法，没有“变量”这个词，也不显示清单里的名字）：

- “连接”卡片只列已经接上的；这个应用没用别人的服务、也没人用它的服务时，页面上没有这张卡片，不是出错。可选的、装的时候没接上的服务不在这里列，用 `acornfox --json status 应用名` 看。v0.6.2 及更早的概览最下面有一张“用到的服务”卡片，v0.6.3 起并进了“连接”。
- “连接”里写着“某某 在用它的数据库，所以现在不能删它”：就是删服务、删应用时的 `CAT-SVC-04`（`in_use`），照 `app-center.md` 的“登记服务”里“删”那一条说，不要为了删它去删在用它的应用。
- “安装设置”只有从应用中心装的应用有；用户自己部署的项目没有这一行，不是出错。这一行现在只能看，不能在页面上改；改设置用 `acornfox apps set`（见 `app-change.md` 的“改一个应用的设置、让它跟上”）。
- “安装设置”那一行带黄点、写着“某一项和现在的不一样”：就是 `APP-VARS-01`，照 `app-change.md` 的“查一个应用是用什么设置装的”第 4 步说，要让它跟上照 `app-change.md` 的“改一个应用的设置、让它跟上”做。
- “安装设置”里看不到接上的服务给的地址、账号、密码，只写它连着谁。用户要看这些值：请他到“设置 › 服务”点开那条服务，或者你运行 `acornfox --json services show 服务名`（保密项只显示后 4 位）。
- 页面上密码和 Key 默认只显示后几位，旁边有“显示”。用户想看完整的，请他自己在页面上点；**不要让他把看到的密码发给你**。

### 公网访问控制台（可选）

只有用户想在手机或别的电脑上直接用网址打开控制台时，才提这个。默认不开放：用户没有明确说要，就不要开。开之前先说清楚：

- 拿到登录密码，就等于拿到这台服务器的 root 权限，因为控制台可以部署任意程序。
- 需要一个用户自己的域名（例如 `panel.example.com`），而且不能是已经给应用用的域名。国内服务器的域名必须已经 ICP 备案。
- 需要在云厂商安全组放行 TCP 80 和 443，并且 80、443 没有被别的程序占用。

用户确认后执行（先只检查一次，看用户还需要做什么）：

```bash
acornfox public-console enable panel.example.com --json --wait 0
```

- `ok:true`：已开通。把 `url` 告诉用户；密码在 `password_file` 指向的文件里（只有用户本人可读），请用户自己打开文件，把密码存进密码管理器后删除该文件。**不要读取或在对话里复述密码。** 如果 `https.code` 不是 `ok`，把 `https.message` 和 `https.hint` 转述给用户。
- `ok:false`：`diagnosis.code`（`dns_unresolved`、`dns_mismatch`、`port_closed`、`port_unreachable`、`icp_blocked`、`wrong_target` 等）照入口“遇到故障编号怎么办”运行 `acornfox faults 诊断码 --json`，用大白话告诉用户怎么做：解析没加或指错了，原样转述 `hint` 里的“主机记录”和“记录值”；端口没放行，请用户到云厂商安全组放行 TCP 80 和 443；域名未备案，国内服务器无法使用，先备案或换一个已备案的域名；域名经过了 CDN 或代理，请关掉。处理完后用 `--wait 10m` 再执行，命令会每 15 秒自动重查，通过后自动开通。

其他命令：

```bash
acornfox public-console status --json                         # 是否开启、地址、HTTPS 是否正常
acornfox public-console enable 域名 --reset-password --json    # 忘记密码时重新生成（PUBCON-05），旧密码和登录会话立即失效；新密码只出现这一次
acornfox public-console disable --json                        # 关闭：移除路由，公网登录的会话全部失效
```

**用户自己在控制台页面上开关**（服务器上的命令照旧能用，不用密码）：控制台页面“设置 › 访问 › 在外面打开控制台”里有“开启公网控制台”和“关闭公网控制台”按钮。默认仍然不开；用户没说要开，不要劝他去点。页面上开之前会弹确认框，并要**再输一次这次登录用的控制台密码**（从局域网控制台登录的输局域网控制台密码；从公网控制台登录的输公网控制台密码，而且那里只能关、不能开或换地址；用 `acornfox open` 进来的不用输）。开启成功后新密码只在页面上显示这一次，请用户当场存进密码管理器；**不要让用户把密码发给你**。配了平台域名时，地址框默认填 `console.平台域名`，也可以换成自己的域名。

**开启以后要等证书（照着说）：** 第一次开启要现申请证书，通常一两分钟。这段时间打开那个地址，浏览器会报“连接不安全”，**这不是故障**。v0.6.3 起页面在开启后先写“正在申请证书”，好了自己变成“证书好了，可以打开了”：请用户等页面这样提示了再打开，不要让他在浏览器的警告页上点“继续前往”。v0.6.2 的页面没有这句提示，请用户开启后等一两分钟再打开。

- 用户说“开了打不开”“提示连接不安全”：先问是不是刚开启。刚开启的，照上面说，请他等。
- 用户说等了好几分钟还不行，或者页面写着“还没签下来”：服务器会自己接着重试，不用关了重开。你运行 `acornfox --json public-console status` 看 `https.code`：`ok` 是已经好了，请用户刷新页面再打开；`cert_pending` 是还在申请，把 `https.hint` 转述给用户，大陆服务器先问这个域名备案了没有，再只读看 `sudo docker logs --tail 50 acornfox-edge`，把和证书有关的几行告诉用户；别的编号照上面那张表处理。
- 页面写着“这台服务器自己确认不了证书好了没有”：有的云不让服务器连自己的公网地址，页面查不了，不是出错。请用户过一两分钟直接打开地址试试；你在用户电脑上（情况乙）运行上面那条 `status` 命令也能查。

页面检查域名没通过时给的编号和上面一样；页面上输密码的几个编号（`PUBCON-01`～`PUBCON-04`）照 `acornfox faults 编号` 查：密码没输或不对，请输这次登录用的那个控制台密码再试；输错太多次，按提示等几分钟再试；这台机器在局域网里没有公网地址（`PUBCON-03`），开不了，局域网里用局域网控制台、人在外面用 `acornfox open`；现在是从公网控制台登录的只能关闭（`PUBCON-04`），要换地址就从局域网控制台或 `acornfox open` 进来再开。

### 局域网打开控制台

家里、办公室局域网里的 Linux 服务器专用：局域网里的电脑、手机用浏览器打开 `http://服务器局域网地址:18802`。**云主机、公网服务器开不了**（`LAN-CONSOLE-01`），用上面的 SSH 隧道或公网访问。

v0.5.1 起的规矩（更早的版本是 `enable` 时生成一个密码，只显示一次）：

- 局域网服务器**第一次安装时默认已经打开**（安装时加 `--no-lan-console` 才不开）；重装、升级不会自动打开。
- **第一次打开时在浏览器里设密码**（至少 8 位），局域网里谁先打开谁设。所以装完要提醒用户现在就去设。
- 登录时勾“记住这台设备 90 天”，90 天内不用再输密码。
- 只认局域网来源的访问，别的来源一律 403（`LAN-CONSOLE-02`）。局域网里不加密，只在可信的网络里用。

#### 最低路径（照着做，不用判断）

```bash
acornfox lan-console status --json
```

按返回值转述，不要自己发挥：

| 返回 | 对用户说什么、做什么 |
| --- | --- |
| `enabled: false` | 没开。用户想开，先确认这台机器在他自己的局域网里，再运行 `acornfox lan-console enable --json`（写操作） |
| `enabled: true`，`password_set: false` | 把 `url` 给用户，请他**现在就**用局域网里的电脑打开设密码（`LAN-CONSOLE-03`） |
| `enabled: true`，`password_set: true` | 把 `url` 给用户；把 `password_set_at`、`password_set_from` 念给他，问“是不是你设的”。`password_set_at` 是 UTC 时间（结尾带 `Z`），先换成用户当地时间再念（国内加 8 小时） |
| `generated_password: true` | 旧版本开的，还在用当时生成的密码，照常能用 |

返回里的 `devices` 是现在记住了几台设备，用户问起再说；要看是哪几台用下面的 `devices`。

其他命令：

```bash
acornfox lan-console reset-password --json   # 写操作：清掉密码，所有登录和记住的设备一起作废；之后请用户重新打开 url 设密码
acornfox lan-console devices --json          # 只读：记住的设备（编号、名称、上次使用时间和地址、到期日）
acornfox lan-console forget 设备编号 --json    # 写操作：让一台设备失效（forget --all 是全部）；重复执行不出错
# 用户只说了“那台手机”“那台 iPhone”没给编号：先 devices --json，按 name 找；只有一台对得上就直接 forget 它，
# 对得上的不止一台就把这几台的名称、上次使用时间和地址列给用户，问是哪一台
acornfox lan-console disable --json          # 写操作：关闭，密码、登录、记住的设备全部清掉
```

#### 忘了控制台密码（固定步骤，v0.7.0 起登录页有“忘了密码”）

什么时候用：用户说“忘了控制台密码”“登录不进去”，或者把登录页“忘了密码”里点“复制给 AI 工作台”得到的那段话贴给你（里面有故障编号 `LAN-CONSOLE-04`，公网入口是 `PUBCON-05`；运行 `acornfox faults 编号` 看完整步骤）。**页面上不能直接重设**：不登录就能重设，等于谁都能抢走控制台，所以重设只能在服务器上做。情况乙、丙经 `ssh 用户@服务器` 运行下面的命令（也可以用电脑上的 `acornfox`，它已经连到这台服务器），情况甲、丁直接运行。

最低路径（局域网控制台，端口 18802）：

1. `acornfox --json lan-console status`（只读）：看 `enabled`、`password_set`、`password_set_at`、`password_set_from`。`enabled: false` 不用重设（返回过 `lan_console_off`）：告诉用户局域网控制台是关着的。
2. 说一句：重设会让**所有登录和记住的设备都退出**，之后要重新登录。用户说的是“忘了密码”，这句话就是同意（上面“必须先问用户的”的例外），不用再问一遍。
3. `acornfox --json lan-console reset-password`（写操作，重复运行不出错）：清掉密码，所有登录状态和记住的设备一起作废。
4. 把 `url` 给用户，请他现在就用局域网里的电脑打开，**自己在浏览器里设新密码**（谁先打开谁设，别拖）。设好后再 `acornfox --json lan-console status`，`password_set` 是 `true` 就好了。新密码不会出现在命令输出里，你也拿不到。

忘的是**公网控制台**（用自己的域名打开的那个入口）的密码：用户说忘了就是同意，运行 `acornfox public-console enable 域名 --reset-password --json`（域名从 `acornfox --json public-console status` 取）。新密码只出现这一次，写在 `password_file` 指向的文件里：请用户自己打开文件、存进密码管理器后删除，**你不要读它、不要在对话里复述**。旧密码和现在的公网登录立刻失效。

可以发挥的地方：解释为什么页面上不能直接重设；用户不在服务器旁、也没有 SSH 时，请他找装 AcornFox 的人，或者到服务器本机的终端里运行同一条命令；`status` 里“设密码的时间和地址”不是用户自己时，把它念给用户听（有可能是局域网里别人抢先设的）。

停下问用户的节点：用户的原因**不是“忘了密码”**（手机丢了、怀疑有人在用、想让所有人下线）时，先问清要的是“只让某一台设备退出”（`acornfox --json lan-console devices` 找到它，再 `forget 设备编号`）还是“所有设备都退出”（`reset-password`），等他回答再动；不要替用户设密码，也不要让用户把密码发到对话里。

#### 必须先问用户的

- `enable`：开之前问。云主机上不要尝试，也不要为了开它去改安全组、防火墙或 `--public-host`。
- `reset-password`、`forget --all`、`disable`：会让所有人掉线，先问。例外：用户自己说了“忘了密码”或“设密码的不是我”，这句话就是同意，直接运行 `reset-password`，不用再问一遍；做完用 `status --json` 确认 `password_set` 是 `false`，再请用户现在就打开 `url` 重新设。重设之前 `password_set` 就已经是 `false`（从没设过，或之前已经重设过），也照样运行一次（重复运行不出错），然后同样请用户打开 `url` 设密码。
- **不要替用户设密码，不要让用户把密码发到对话里。** 密码只在浏览器里输入。

#### 出错先看哪里

- 浏览器里 403、页面写着 `LAN-CONSOLE-02`：访问的人不在局域网里，从外面进用 `acornfox open`。
- `enable` 返回 `LAN-CONSOLE-01`：云主机或公网服务器，或服务刚启动还没判断出来；局域网机器等十几秒再试一次，云主机改用 `acornfox open`。
- `acornfox doctor` 警告 `LAN-CONSOLE-03`：开着但没设密码，请用户现在去设，或者 `disable`。
- 浏览器打不开 `url`：先 `status` 看开没开；再看电脑和服务器是不是同一个局域网、服务器防火墙有没有拦 18802。

## 绑定域名

绑域名前确认三件事：安装时没用 `--allow-busy-80-443`（80、443 归 AcornFox）；安全组放行了 80、443；域名已解析到服务器公网 IP（国内服务器的域名必须已 ICP 备案）。然后在项目目录执行 `acornfox domain add 域名 --json`，证书自动申请。

绑好后（v0.6.0 起）`acornfox --json status 应用名` 里的地址是 `https://域名`，告诉用户用这个地址打开。从应用中心装的应用，清单里用到应用地址的，要重新生效才会换成域名（v0.7.0 起 `domain add`、`domain remove` 自己先算计划：会重启它的，要用户同意后加 `--yes`，不加报 `APP-APPLY-05`、域名什么都没改；用户不想现在重启加 `--no-reapply`，之后照 `app-change.md` 的“改一个应用的设置、让它跟上”再对；`apps vars` 里的 `APP-VARS-01` 就是还没对上）。

## 平台域名（整台服务器一个域名）

给整台服务器配一个域名（例如 `apps.example.com`），访问方式是“公网”的应用自动多一个地址 `https://应用名.平台域名`，证书自动申请，不用记端口。应用自己绑的域名（上一节）优先；原来带端口的地址照常能用；只本机、局域网、只在内部网络的应用不受影响。设了平台域名**不会**把应用改成公网，改不改仍由用户在每个应用上定（见 `app-center.md` 的“对外开放”的规矩）。用户说“给这台服务器配个域名”“所有应用都用域名打开”时用这一节；只想给一个应用绑域名用上一节。

**最低路径（照着做）：**

1. 运行 `acornfox --json domain base`，看现状：
   - `supported` 是 `false`（`unsupported.code` 是 `PDOMAIN-02`）：原样告诉用户 `unsupported.text`，再说“要在外面打开应用，可以用 `acornfox open 应用名`”。到此为止。
   - `state` 是 `unset`：接第 2 步。
   - `domain` 已经有值：用户要换成别的或清掉，跳到下面“必须先问用户的”。
2. 问用户要用哪个域名（要是他自己的、能改解析的域名，通常是一个子域，例如 `apps.example.com`）。拿到后运行 `acornfox --json domain base set 域名 --plan`（只看会怎样，什么都不改），从输出里取 `record`，照这样告诉用户：
   > 请到你买域名的地方加一条记录：名字 `<record.name>`、类型 `<record.type>`、指向 `<record.value>`（完整写法 `<record.full>`）。中国大陆的服务器，这个域名要先备案。加好了告诉我。

   `--plan` 返回 `PDOMAIN-05`：域名写法不对，照 `hint` 请用户只给域名本身。
3. 用户说加好了，运行 `acornfox --json domain base set 域名`。
4. 看输出的 `checks`（`dns` 域名指过来没有、`ports` 外面能不能连上 80 和 443、`cert` 证书）和 `state`：
   - `state` 是 `ok`：告诉用户平台域名配好了，`apps` 里 `active` 是 `true` 的应用现在用 `https://应用名.平台域名` 打开（原样念 `apps[].url`）。有一项 `waiting` 是 `true` 时把它的 `text` 也告诉用户（例如“还没有开放到公网的应用，开放一个以后再检查”“证书正在自动申请，几分钟后再检查”），这不是故障。
   - `state` 是 `problem`：把 `problem.text`、`problem.detail`、`problem.next` 原样告诉用户，按编号处理：

   `problem.code`（`PDOMAIN-…`）照入口规则 `acornfox faults 编号 --json` 查，几个先知道：

   - `PDOMAIN-01`：记录还没加好、没生效或指错了，照 `problem.next` 请用户改，几分钟后再运行 `acornfox --json domain base` 重新检查。
   - `PDOMAIN-03`：外面连不上 80 或 443，先 `sudo acornfox doctor` 看入口代理和端口占用；安全组、防火墙**问用户**同意后由用户放行 TCP 80、443。
   - `PDOMAIN-04`：证书没签下来，大陆服务器先问域名备案了没有；只读看 `sudo docker logs --tail 50 acornfox-edge`，把和证书有关的几行告诉用户。

5. 某个应用在 `apps` 里 `active` 是 `false`：`note` 是“改成公网后自动生效”的，说明它现在不是公网、不用处理（要开放到公网照 `app-center.md` 的“对外开放”的规矩先问用户）；`note` 带 `PDOMAIN-06` 的，原样转述，办法是给它单独绑一个域名（上一节）。

**必须先问用户的：**

- **换掉**已有的平台域名、**清掉**平台域名：所有应用在旧域名下的地址都会打不开。先运行 `acornfox --json domain base set 新域名 --plan`（清掉是 `acornfox --json domain base clear --plan`），把 `plan.say` 和每个应用 `url` → `url_after` 的变化告诉用户，用户明确同意后再加 `--yes` 运行。不带 `--yes` 会被拒绝（`PDOMAIN-07`），**不要**自己加 `--yes`。
- 放行安全组、防火墙，改服务器地址。

**可以发挥的地方：** 解释域名、记录、证书是什么；帮用户判断用哪个子域；用户已经给各应用单独绑了域名时，说明两者可以并存。

设平台域名、换掉或清掉以后，清单里用到应用地址的应用，应用里写的地址还是旧的，不会自己重启（输出里 `apps_behind` 是这些应用，`acornfox --json apps affected` 也列）；问用户要不要让它们跟上，同意后照 `app-change.md` 的“改一个应用的设置、让它跟上”里“平台上的值变了”那一段做。

## 可以发挥的地方

- 解释控制台、隧道、局域网、公网、域名、证书是什么，帮用户判断用哪种方式打开；用户已经给各应用单独绑了域名时，说明和平台域名可以并存。
- 用户想自己在页面上看时，照“用户问‘在页面上哪里看’”那张表告诉他位置。

## 必须先问用户的

- 开局域网控制台（`lan-console enable`，先确认这台机器在他自己的局域网里）；`reset-password`、`forget --all`、`disable` 会让所有人掉线，先问（用户自己说了“忘了密码”例外）；不要替用户设密码，也不要让用户把密码发到对话里。
- 对公网开放控制台：用户明确要了才做，先说清风险；开之前页面上会弹确认框并要再输一次控制台密码，**不要让用户把密码发给你**。
- 关掉后台隧道（`acornfox open --stop`）：用户说不用了才关。
- 换掉、清掉平台域名：先 `--plan`，用户明确同意后才加 `--yes`；放行安全组、防火墙（TCP 80、443）、改域名解析：由用户决定和操作。
- 把应用改成公网、绑域名要重启应用时：先问，用户同意再加 `--yes`。
